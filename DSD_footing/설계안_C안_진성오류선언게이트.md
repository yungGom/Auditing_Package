# C안 설계안 — 진성오류 선언 게이트

승인 대기. **구현 착수 금지.**

## 0. 왜 필요한가 (한 줄)

지금 `GATES.json`은 `A_DIFF`를 **골든으로 저장**한다. 도구가 오탐을 내면 그 숫자가
"정답"으로 굳고, 진짜 차이 1건이 사라지고 오탐 1건이 생겨도 건수가 같아 통과한다.
정답셋은 "회계사가 찾은 차이"라 **도구만 틀린 오탐을 원리적으로 못 잡는다.**

## 0-1. 선행 조사 결과 (구현 전 실측)

**(가) L2는 게이트에 안 붙어 있다 — 확인됨.**
`run_gates.py`는 `final.py` 전역에서 `stat·B·RLINKS·RUN·RDIFF·gap·miss·unref·npara·
pros·cons·nounit·FCON` 13개만 읽는다. `L2_RES`는 읽지 않는다. 게다가 L2는 **회사 사전이
그 문서에 적용될 때만** 돌고(`labels/조선내화.json`의 `applies_to`), 등록 4축은 어느
것도 해당하지 않아 **아예 실행되지 않는다.**

**(나) L2를 게이트에 붙이는 비용 — 실측.**

| 단계 | 시간 |
|---|---|
| `l2_extract.extract` (PDF 재파싱) | 2.93s |
| `l2_labels.build` (매칭) | 0.01s |

**등록 4축은 사전이 없어 추가 비용 0s.** 조선내화 반기연결을 축으로 등록하면 그 축에서만
약 3초가 는다(이미 `final.py`가 지불하는 비용이라 실질 증가분은 0 — `run_gates.py`가
같은 실행의 전역을 읽기만 하면 된다).

**(다) L2 `confirmed` 11건은 선언 기반 키를 갖고 있다 — 중요.**
각 항목이 `canonical_label` / `period_key` / `table_a` / `table_b`를 갖는데, 이 넷은
**회사 사전에서 온 값**이지 추출에서 온 값이 아니다. 페이지·행 인덱스와 달리 조판 인식이
바뀌어도 흔들리지 않는다. 지분법손익 2건이 `table_b`(n17-t1 vs n6-t1)로만 갈리므로
네 값이 모두 키에 필요하다.

## 1. 스키마 — 파일을 분리한다

### 1-1. 왜 분리하는가 (승인 요청 §3의 답)

`gates.py:56`은 `--update-gates`에서 **문서 전체를 `json.dump`로 다시 쓴다.** 값은
보존되지만 **서식이 재작성된다** — 실제로 이번 라운드에서 `_unresolved` 블록이 한 줄
dict에서 여러 줄로 펼쳐졌다(diff 25줄 중 21줄이 서식 변경). 선언값이 같은 파일에 있으면:

- 회계사 승인 사항인 선언값이 **골든 갱신 때마다 diff에 섞인다** → 커밋 리뷰에서 안 걸린다
- 미래에 쓰기 경로를 손대면 선언값이 함께 날아갈 위험이 있다

→ **`ERRORS.json` 별도 파일.** `gates.py`는 이 파일을 **읽기만 한다. 쓰기 코드 없음.**
어떤 CLI 플래그로도 갱신되지 않는다.

## 2. 식별 키 — L1과 L2를 다르게 쓴다

### 2-1. L1: `p{page}|{check}|{disp}|{diff}`

제안하신 (페이지, 계정과목, 차이금액)에서 **계정과목을 빼고 공시금액을 넣는 안**을
제시한다. 근거:

- **계정과목은 조판 인식에 종속된다.** 라벨 열 선정을 이미 한 번 바꿨다(`c0` 고정 →
  "첫 금액열 왼쪽 첫 TEXT 셀", 침묵 미검증 목록에 등재된 변경). 또 바뀌면 키가 깨진다.
- **공백 변형에 취약하다.** 실물이 `자 본 총 계`(공백 3개)다. 정규화 규칙이 바뀌면
  같은 항목이 다른 키가 된다.
- **공시금액은 회계사가 지면에서 읽는 바로 그 숫자다.** 표시 문자열이 아니라
  `evidence.disp` 수치를 쓰므로 `(3,405,862)` vs `-3,405,862` 표기 차이에 영향받지 않는다.
- `check`(A1/A2/A3/A5)를 넣어 같은 행의 세로합·가로합을 구분한다.

**계정과목은 키가 아니라 `account` 필드로 함께 적는다** — 회계사가 선언 파일을 읽을 때
숫자만 있으면 무엇인지 알 수 없기 때문이다. 로더는 `account`가 실제와 달라도 **경고만**
내고 키로 대조한다(사람이 읽는 주석이지 대조 대상이 아니다).

**현행 15건 유일성 실측: 충돌 0건.** LGES p6 두 건은 `disp`가 달라(15,493,441 /
15,717,080) 갈린다.

⚠ **한계를 명시한다**: 이 키는 추출 결과에서 만들어지므로, 조판 인식이 크게 바뀌면
키도 바뀐다. 그때는 게이트가 "선언에 없는 DIFF"로 실패하고 **회계사가 다시 판정한다** —
이것이 오작동이 아니라 의도된 동작이다. 조판 인식이 바뀌었으면 판정도 다시 봐야 한다.

### 2-2. L2: `{canonical_label}|{period_key}|{table_a}|{table_b}`

**네 값 모두 회사 사전에서 온다** — 추출 결과가 아니다. L1 키보다 근본적으로 안정적이다.
페이지가 바뀌어도, 행 인덱스가 바뀌어도 키는 그대로다. 판정 단위가 쌍(11)이라는 확정과도
정확히 맞는다(마크 10건이 아니라 `confirmed` 배열 11건이 그대로 키가 된다).

## 3. 실패 조건 — 집합 비교

```
실측 DIFF 집합  D = { key(x) : x ∈ 이번 실행의 DIFF }
선언 집합       S = accountant_confirmed_errors ∪ known_false_positives

실패 ①  D − S ≠ ∅   미선언 DIFF 출현 → "회계사 판정이 필요합니다"
실패 ②  S − D ≠ ∅   선언됐는데 사라짐 → "선언 항목이 더 이상 발화하지 않습니다"
```

**실패 ②가 핵심이다.** 건수 비교로는 "진짜 1건이 사라지고 오탐 1건이 생김"을 못 잡지만,
집합 비교는 ①과 ② 양쪽에서 동시에 잡는다.

②는 좋은 변화(오탐을 고쳐 사라짐)일 때도 발화한다. **그게 맞다** — 선언을 지우는 것은
회계사의 결정이고, 도구가 조용히 지우면 안 된다. 메시지로 구분한다:

```
[ERRORS] 선언 항목이 발화하지 않습니다 (오탐을 고쳤다면 ERRORS.json에서 그 항목을 지우십시오):
[ERRORS]   p43|A1|169447|673268  합 계 — 과제7(롤포워드 마지막 합계행)
```

L2도 같은 방식으로 `l2_confirmed_pairs`와 실측 `confirmed` 집합을 비교한다.

## 4. 갱신 권한 — 세 겹으로 막는다

1. **파일 분리** — `ERRORS.json`. `gates.py`에 이 파일을 **쓰는 코드가 없다.**
   `--update-gates`는 `GATES.json`만 건드린다.
2. **플래그 없음** — `--update-errors` 같은 것을 만들지 않는다. 사람이 편집기로만 고친다.
3. **diff 가시성** — 선언 1건 = JSON 1블록이라 추가·삭제가 커밋 diff에서 그대로 보인다.
   `confirmed_by` / `confirmed_at`이 함께 바뀌지 않으면 로더가 경고한다(누가 언제
   판정했는지 없는 선언은 추적 불가).

**추가 제안 (승인 요청)**: `.githooks` pre-commit에 "`ERRORS.json`이 스테이지에 있으면
경고 1줄"을 넣을지. 막지는 않고 "선언값 변경이 포함되어 있습니다 — 회계사 승인 건인지
확인하십시오"만 띄운다. `[되돌리기 쉬움]`

## 5. 신규 축 기본값 — 선언 없음 = 실패, 단 메시지로 구분

말씀대로 기본값 0이 맞다. 다만 **"선언 0건"과 "선언 파일에 아예 없음"을 구분**한다 —
전자는 "판정 결과 진성·오탐 모두 없음"이고 후자는 "아직 판정 전"이다. 같은 실패로
뭉뚱그리면 회계사가 무엇을 해야 하는지 모른다.

```
[ERRORS] *** 선언 없음: '[신규회사]감사보고서.pdf' ***
[ERRORS]   DIFF 7건이 나왔으나 이 축의 판정 선언이 ERRORS.json에 없습니다.
[ERRORS]   회계사가 전건을 진성/오탐으로 판정한 뒤 등록하십시오.
[ERRORS]   판정용 목록: python diff_list.py <pdf>   ← §7 참고
```

DIFF가 0건이면서 선언도 없으면 **통과시킨다**(대조할 것이 없다). 판정할 것이 없는 축에
등록을 강요할 이유가 없다.

## 6. 조선내화 반기연결 축 등록 — L1과 L2를 나눠 담는다

같은 축 항목 안에서 **배열을 분리**한다(§1-2 스키마 그대로):

- `accountant_confirmed_errors` / `known_false_positives` → **L1 전용**, 현재 둘 다 `[]`
- `l2_confirmed_pairs` → **L2 전용**, 11건

이렇게 나누는 이유: L1과 L2는 검증 성격도 키 체계도 다르다(§2). 한 배열에 섞으면 키
형식이 두 가지가 되어 로더가 어느 쪽인지 추측해야 한다.

**L2 지표를 `GATES.json`에도 넣는다**: `L2_confirmed` / `L2_undeclared` / `L2_excluded`.
⚠ **사전이 적용되지 않는 축에서는 이 지표를 기록하지 않는다 — 0으로 적지 않는다.**
0은 "검사했고 없었다"는 뜻인데 실제로는 "검사하지 않았다"이기 때문이다(미매칭 ≠ 0).
`run_gates.py`가 `L2_RES is None`이면 세 지표를 metrics dict에 아예 넣지 않는다.

## 7. `run_gates.py` 변경 — 전역 2개를 더 읽는다

`final.py`는 수정하지 않는다. 이미 필요한 값을 전역으로 갖고 있다.

| 읽을 전역 | 용도 |
|---|---|
| `exc` | 예외색인 행 — `판정=="차이"`인 것만 걸러 L1 DIFF 집합 생성 (`[pi,ti,kind,label,unit,disp,calc,diff,...]`) |
| `L2_RES` | `confirmed` 배열 → L2 쌍 집합 + `L2_*` 지표 |

새 모듈 `errors.py`(로더 + 대조)를 만들고 `run_gates.py`가 호출한다. `gates.py`는
건드리지 않는다 — 골든 대조와 선언 대조는 성격이 다르고, 섞으면 `--update-gates`가
선언에 닿을 위험이 생긴다.

**판정용 목록 생성기**: 지금 스크래치패드에 있는 xlsx 생성 스크립트를 `diff_list.py`로
저장소에 편입할지 승인 요청. 신규 축 등록 때마다 필요하고, 성분 합 자체 검증(결정 25)이
들어 있어 재현 실패를 잡아준다. `[되돌리기 쉬움]`

## 9. 게이트 계획

1. 현행 상태로 `errors.check()` 실행 → **5축 전부 통과**해야 한다(선언이 실측과 일치)
2. **음성 테스트 3종** — 통과만 확인하면 게이트가 작동하는지 알 수 없다(결정 27의 교훈):
   - 선언 1건을 지운다 → 실패 ①(미선언 DIFF)이 뜨는가
   - 선언에 가짜 1건을 넣는다 → 실패 ②(발화하지 않음)가 뜨는가
   - `reason`을 비운다 → 선언 거부로 실패하는가
3. 신규 축 시뮬레이션 — `ERRORS.json`에 없는 축을 돌려 §5 메시지가 뜨는가
4. `--update-gates` 실행 후 `ERRORS.json`이 **바이트 단위로 불변**인가 (§4-1의 실증)
5. 기존 게이트 무영향 — RENDER_GATE·GATES·glyph_gate

## 10. 이 설계가 못 하는 것 (명시)

- **선언 자체가 틀리면 막을 수 없다.** 회계사가 오탐을 진성으로 판정하면 게이트는 통과한다.
  이 게이트는 "판정되지 않은 것이 조용히 지나가는 것"을 막을 뿐이다.
- **DIFF가 아닌 침묵 미검증은 여전히 안 잡힌다.** A5 커버리지(결정 23)·예외 계수(결정 27)가
  담당하는 영역이고, 이 게이트의 범위 밖이다.
- **키가 바뀌면 재판정이 필요하다.** §2-1의 한계. 조판 인식 변경 시 회계사 부담이 는다.
