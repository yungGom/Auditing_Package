# run.bat + 시작 화면 설계안

승인 대기. **구현 착수 금지.** 범위는 `ui/` 아래 + `run.bat`(+ README 갱신).

## 0. 기존 `run.bat`과의 차이 — 요구하신 사전 보고

**현재 동작**: PDF를 드래그 → `python foot.py "%~1"` 실행 → 콘솔에 결과 출력 →
`pause`. **UI를 띄우지 않는다.** 분석만 하고 끝난다. 한글·괄호·대괄호 경로
(`[조선내화]반기연결검토보고서(2026.08.13).pdf`)로 실측 확인 — 정상 동작한다
(cmd 기본 코드페이지 949, `chcp` 없이).

**바뀌는 것**: 실행하면 UI 창이 뜨고, 그 창 안에서 파일을 골라 분석부터 검토까지
이어진다. 드래그해도 여전히 되지만(인자로 넘어가므로), **주된 사용법이 "실행 →
버튼 클릭"으로 바뀐다.** 콘솔 전용 산출물(예외색인·틱마크 PDF)은 그대로 나온다 —
UI는 그 위에 얹히는 것이지 대체하는 것이 아니다.

## 1. 전체 흐름

```
run.bat (인자 없음)
  → cmd: python 존재 확인 → 의존성 확인 → 통과 시 UI 프로세스 실행, cmd 최소화
  → PyWebView 창: 시작 화면(start.html)
      [보고서 열기] 버튼 → OS 파일 선택 대화상자(PDF 필터)
      최근 연 보고서 목록 (ui/config.json)
      검토자 이름 (미입력이면 여기서 입력)
  → 파일 선택(대화상자 또는 최근 목록 클릭)
      ├─ sha256(선택한 파일) == 기존 marks.json의 source.sha256
      │    → 분석 건너뛰고 바로 검토 화면(viewer)
      └─ 다름/marks.json 없음
           ├─ 기존 <원본>_판단.json 있고 sha256 다름 → 경고 대화상자, 확인 필요
           └─ 진행 → subprocess로 foot.py 실행, 진행 표시 → 완료 시 viewer로 전환

run.bat "<PDF 경로>"  (드래그 또는 인자 직접 지정)
  → 시작 화면 건너뛰고 위 "파일 선택" 이후 흐름과 동일하게 진입
```

같은 창 안에서 화면이 바뀐다 — `webview.Window.load_url()`로 `start.html` →
`viewer index.html`을 전환한다(실측: pywebview가 지원, 새 창을 열지 않음).

## 2. 진행 표시 — 승인이 필요한 지점

**조사 결과**: `final.py`는 지면별 진행 로그를 전혀 안 낸다(현재 콘솔 출력은
분석 끝난 뒤 요약 한 줄뿐). 그래서 "N/M 페이지" 같은 정확한 진행률은 **`ui/`
바깥(`final.py`)을 건드리지 않고는 만들 수 없다.**

**A안 — `final.py`에 진행 훅 1줄 추가 (범위 예외, 별도 승인 필요)**
페이지 루프 안에 `if PROGRESS_CB: PROGRESS_CB(pi, total)` 한 줄만 추가하고
기본값은 `None`(콘솔 실행 시 아무 영향 없음). 판정값·렌더 바이트에 영향 없음 —
`stat`/`MARKS`/`OUT_PDF` 등 어떤 것도 안 건드리는 순수 콜백이라 5축 게이트는
그대로 통과할 것으로 예상되나, **범위를 벗어나므로 별도 승인 없이는 안 건드린다.**
`[되돌리기 쉬움]` — 한 줄 제거로 원복.

**B안 — 범위 안에서 타협 (기본, 승인 없이 진행 가능)**
페이지 수는 미리 안다(pdfplumber로 PDF를 한 번 열어 `len(pdf.pages)`만 읽음 —
분석 자체는 건드리지 않는 read-only 조회). 진행 표시는 **"분석 중… (총 N페이지,
경과 M초)"** + 스피너로, 실제 처리된 페이지 수가 아니라 경과 시간만 보여준다.
30초를 넘기면 **"보통보다 오래 걸리고 있습니다. 페이지가 많거나 표가 복잡한
문서일 수 있습니다"**로 문구를 바꾼다(죽었다고 오판하지 않게, 그러나 진짜 정지와
구분은 못 함 — 이게 B안의 한계).

**추천**: B안으로 시작하고, 실사용해보고 "경과 시간만으로는 불안하다"는 게
확인되면 그때 A안을 별도 요청으로 승인받는다. 지금 껀 U-6도 아니고 판정 파이프라인도
아니라 두 안 다 안전하지만, 지시하신 범위(`ui/` + `run.bat`)를 지키는 쪽이 B안이다.

## 3. 판단 파일 보호 — 가장 중요한 부분

핵심 사실관계부터: **`foot.py`는 `_판단.json`의 존재를 전혀 모른다.** 그 파일을
쓰는 곳은 U-6의 `ui/api.py`뿐이라, 분석을 다시 돌려도 **판단 파일 자체가 지워지거나
덮어써지는 일은 구조적으로 없다.** 이미 있는 안전장치(U-6, 결정 30)는 **읽을 때**
sha256이 다르면 적용을 거부한다.

그런데 이번 요청이 만드는 새 위험은 다르다: **분석이 자동으로, 사용자가 "지금
재분석한다"고 의식하지 못한 채 트리거된다.** 사람이 `python foot.py`를 직접 친
게 아니라 "열기"를 눌렀을 뿐인데 뒤에서 재분석이 돈다 — 그 결과 기존 판단이
새 marks.json에 안 맞게 될 수 있다는 사실을 **사후에(검토 화면에서 경고를 보고서야)**
알게 되는 것이 문제다. 사전에 알려야 한다는 지시를 그대로 반영한다.

**흐름**:
```
1. 사용자가 PDF 선택(경로 P) 확정
2. sha256(P) 계산 (marks.sha256_of 재사용 — 새 해시 코드 안 만듦)
3. <base>_marks.json 있고 그 source.sha256 == sha256(P)?
     예 → 분석 건너뛰고 바로 검토 화면 (§4)
4. <base>_판단.json 있음?
     아니오 → 그냥 분석 진행 (처음 보는 문서)
     예 → 그 source_sha256 == sha256(P)?
            예 → 그냥 분석 진행 (내용 동일 — R-1 결정론상 재분석해도 같은 marks.json이
                 나와 기존 판단이 그대로 들어맞는다. 정보성 메시지만: "기존 판단
                 N건을 이어서 사용합니다")
            아니오 → ⚠ 진행 중단, 대화상자로 경고:
                 "이 보고서에 대한 기존 판단 기록이 있습니다만, 지금 선택한 파일과
                 내용이 다릅니다(원본이 바뀐 것으로 보입니다).
                 재분석해도 기존 판단 파일 자체는 지워지지 않지만, 새 분석 결과와는
                 안 맞아 자동 적용되지 않습니다.
                 [계속 진행]  [취소]"
                 [계속 진행] 선택 시: <base>_판단.json을
                 <base>_판단.json.bak-<타임스탬프>로 복사(보험용 — 되돌리기
                 쉬움, 실수로 다른 파일을 고른 경우 대비) 후 분석 진행
```

## 4. 이미 분석된 보고서 — 재분석 생략

§3의 3번 분기 그대로. `marks.json`이 있고 그 `source.sha256`이 지금 고른 파일과
같으면 **`foot.py`를 아예 실행하지 않는다.** 200페이지 문서를 검토 중 창을 닫았다
다시 여는 실무 패턴에 정확히 맞는다.

## 5. 분석 중 창을 닫으면 — 결정

**중단시키고, 부분 산출물을 지운다.** 근거:
- `final.py`는 페이지 루프(대부분의 시간) 동안 아무 파일도 안 만들고, 루프가 끝난
  뒤 `marks.json` → `_틱마크.pdf` → `_예외색인.xlsx` 순서로 쓴다(실측: `final.py`
  코드 순서 확인). 루프 도중 죽으면 **애초에 파일이 없어 정리할 것도 없다.**
  `marks.json` 쓰기 도중(드묾, 아주 짧은 구간) 죽으면 잘린 JSON이 남을 수 있으므로
  — 그 파일이 있으면 지운다(재실행 시 새로 만들면 그만이라 잃을 게 없다. `_판단.json`은
  건드리지 않으므로 안전).
- 분석 결과는 결정론적(R-1)이라 다시 열면 처음부터 다시 돌리면 되고 손해는 시간뿐이다.
  판단 파일이 위험한 것과 성격이 다르다.
- 백그라운드로 계속 돌리는 안은 기각: 창이 닫혔는데 진행 상황을 보여줄 데가 없고,
  다음 실행에서 "지금 어디선가 분석이 돌고 있다"를 알 방법이 없어 오히려 혼란을 준다.

## 6. 최근 목록

`ui/config.json`에 `recents: [{path, name, last_opened}]` (최대 10개, 최신순).
`.gitignore`는 이미 `ui/config.json`을 덮고 있다(U-6) — 별도 조치 불필요.

**경로가 사라진 항목**: 회색 처리 + 클릭 시 "파일을 찾을 수 없습니다 — 목록에서
지우시겠습니까?" 확인 후 제거. 조용히 전부 지우지 않는 이유: 회색으로라도 남아
있으면 "내가 이 파일을 연 적이 있었다"는 사실 자체가 정보다(경로가 잠깐 오프라인인
외장 드라이브·네트워크 폴더일 수도 있음). `[되돌리기 쉬움]`

## 7. `run.bat` 설계

```bat
@echo off
rem ASCII only — chcp 65001은 cmd 오프셋 버그가 있다(기존 run.bat 주석, 실측 유지).
cd /d "%~dp0"

where python >nul 2>nul
if errorlevel 1 (
  echo [ERROR] Python was not found on PATH.
  echo Install Python 3.10+ and make sure "python" works from this folder.
  pause
  exit /b 2
)

python ui\preflight.py
if errorlevel 1 (
  pause
  exit /b 2
)

rem UI가 뜬 뒤엔 이 콘솔이 방해되지 않아야 한다. 완전히 숨기지 않고 최소화만
rem 한다 — 처리되지 않은 예외의 트레이스백이 여기로 나오므로, 죽었을 때 복구해
rem 볼 수 있어야 한다(§8 근거).
start /min "" python ui\app.py %*
```

**`ui/preflight.py` (신규)** — `pdfplumber`/`pypdf`/`reportlab`/`openpyxl`/`webview`를
하나씩 `import`해 **어느 것이 없는지 이름으로 콕 집어** 알려준다(막연히
"ModuleNotFoundError"만 보여주지 않음). `pip install -r requirements.txt` 안내까지
같이 낸다.

**콘솔 처리 — `start /min`을 추천하는 이유(대안과 비교)**

| 안 | 동작 | 위험 |
|---|---|---|
| **최소화 유지(추천)** | 콘솔이 작업표시줄에만 존재 | 없음 — 처리되지 않은 예외가 여전히 거기 찍히고, 최소화 해제로 바로 볼 수 있다 |
| `pythonw.exe`로 완전 숨김 | 콘솔 자체가 없음 | 처리되지 않은 예외가 **어디에도 안 남는다.** 감사 도구에서 조용한 실패는 이 프로젝트의 절대 규칙("미매칭 ≠ 0")과 정신이 안 맞는다 |

`pythonw.exe`는 사람이 코드를 안 읽고 확인할 방법을 없애므로 기각. 최소화가
"방해되지 않으면서도 복구 가능"을 동시에 만족한다.

## 8. 파일 선택 대화상자 — 오프라인 확인 완료

`webview.Window.create_file_dialog()`의 Windows 백엔드는 **`System.Windows.Forms.
OpenFileDialog`**(WinForms, .NET COM `IFileDialog` 래핑)를 직접 쓴다 — 실측으로
소스를 확인했고, 네트워크 호출이 전혀 없는 순수 로컬 OS API다. 오프라인 제약과
무관.

## 9. `Api` 확장 (ui/api.py)

| 메서드 | 역할 |
|---|---|
| `list_recents()` | 최근 목록(존재 여부 포함) |
| `pick_report()` | 파일 대화상자 → 선택 경로 반환 |
| `open_report(path)` | §3 흐름 전체 실행. 진행 중 `window.evaluate_js`로 진행 상태를 push |
| `confirm_reanalyze(path)` | §3의 경고 확인 후 진행(승인 시 `.bak` 복사 포함) |
| `cancel_analysis()` | 진행 중 취소(§5) |

`Api.__init__`이 PDF 없이도 생성 가능하도록 바뀐다(현재는 `pdf_path` 필수) —
시작 화면에서는 아직 대상이 없다.

## 10. README 갱신

"실행" 절을 시작 화면 흐름으로 다시 쓴다. 콘솔 전용(`python foot.py`) 사용법은
"고급/스크립트 실행" 절로 남긴다 — 배치 처리·CI 등에 여전히 유효하므로 지우지
않는다.

## 11. 게이트 계획

| # | 확인 |
|---|---|
| 1 | 한글·괄호·대괄호 경로 — 대화상자 선택 + 인자 전달 양쪽 |
| 2 | sha256 일치 시 분석 생략(전수 재실행 없이 검토 화면 진입 시간 측정) |
| 3 | 판단 파일 sha256 불일치 → 실제로 경고 대화상자가 뜨고, [취소] 시 분석이 안 도는가(음성 테스트: 강제로 다른 내용으로 재저장한 PDF로 재현) |
| 4 | [계속 진행] 시 `.bak` 파일이 실제로 생기는가, 원본 `_판단.json`은 그대로인가 |
| 5 | 분석 중 창 닫기 → subprocess 종료됨(프로세스 목록 확인) + 부분 산출물 없음 |
| 6 | 최근 목록 — 없는 경로 회색 처리, 클릭 시 확인 후 제거 |
| 7 | `run.bat` 인자 없이 실행 → 시작 화면, 인자 있이 실행 → 건너뜀(둘 다 실제 cmd로) |
| 8 | 의존성 하나를 임시로 이름 바꿔 preflight가 정확히 그 이름을 집어내는지(음성 테스트) |
| 9 | **5축 무영향** — RENDER_GATE·GATES·ERRORS·glyph_gate |

## 12. 승인 요청

1. **§2 진행 표시 — B안(경과시간)으로 시작, A안(final.py 훅)은 보류·별도 승인**
2. **§3 판단 파일 보호 흐름 전체** (경고 대화상자 + `.bak` 복사)
3. **§5 분석 중 창 닫기 → 중단 + 부분 산출물 정리**
4. **§6 최근 목록 — 회색 처리 + 확인 후 제거**
5. **§7 콘솔 처리 — `start /min`(최소화 유지, `pythonw.exe` 기각)**
6. 설계안 전체 — 구현 착수 승인
