# DSD Footing 자동화 도구

DART 감사보고서 PDF의 표시 수치 상호 정합성(풋팅)을 자동 검증하는 감사 실무 도구.
원본 지면에 틱마크를 오버레이한 PDF와 예외 색인 엑셀을 산출한다.

## 실행

```bash
python foot.py <보고서.pdf>
```
같은 폴더에 `<원본이름>_틱마크.pdf`(오버레이 지면) / `<원본이름>_예외색인.xlsx`가
생성된다. `run.bat`에 PDF를 드래그해도 된다.

지면 보기(UI 셸): `python ui/app.py <원본이름>_틱마크.pdf`

옵션·산출물 상세는 `CLAUDE.md` 참고.

## 보안 — IT팀 문의 대응용

한국 회계법상 고객 기밀 유지 의무에 따라, 이 도구는 **완전 오프라인**으로
동작하도록 설계됐다. 아래는 "완전 오프라인"이 정확히 무엇을 뜻하는지, 그리고
확인 방법이다 — 소속 법인 IT팀·정보보안팀 질의에 이 표를 그대로 근거로 쓸 수 있다.

**정의**: "완전 오프라인"은 **이 저장소가 작성한 코드가 외부와 통신하지 않는다**는
뜻이다. 이 도구가 실행되는 Windows 운영체제 자체의 시스템 컴포넌트(WebView2 등)
동작까지는 이 도구가 통제할 수 없다 — 그건 Edge·Office·탐색기 미리보기가 이미
하고 있는 것과 같은 성격의 OS 동작이다.

| | 이 도구가 작성한 코드 | Windows 시스템 컴포넌트(WebView2 런타임) |
|---|---|---|
| 감사 데이터가 나가는가 | **절대 아니다.** PDF·수치·회사명 등 어떤 형태로도 외부 전송 코드가 없다 | 관여 없음 — 감사 데이터를 볼 수 있는 경로 자체가 없다 |
| 무엇이 나갈 수 있는가 | 아무것도 없음(fetch/XHR 호출 0건) | 런타임 자체의 버전 정보(컴포넌트 업데이트 체크로 추정) |
| 로컬 포트를 여는가 | **아니다.** PDF는 `file://`로 직접 열고, 화면 UI는 프로세스 내부 호출(브리지)로 데이터를 받는다 — 네트워크 서버가 없다 | 없음(포트를 열지 않는다 — 나가는 접속만 있을 수 있음) |
| 확인 방법 | `netstat -ano \| findstr LISTENING` 실행 → 이 도구의 python.exe/msedgewebview2.exe(이 도구가 띄운 자식 프로세스, 작업 관리자 "세부 정보" 탭에서 PID로 확인)가 목록에 없어야 함 | `netstat -ano \| findstr ":443"` → msedgewebview2.exe PID의 접속이 보일 수 있음(위 표의 "무엇이 나갈 수 있는가" 참고) |
| 끄고 싶다면 | 해당 없음(원래 아무것도 안 함) | `tools/harden_webview2.ps1` (선택 사항, 기본 배포에 미포함 — IT팀이 직접 검토 후 적용) |

**외부 라이브러리**: `pdfplumber`/`pypdf`/`reportlab`/`openpyxl`/`pywebview` 전부
로컬 설치(pip)로 동작하며, 실행 중 인터넷을 쓰지 않는다. `playwright`는 이 도구를
만드는 개발자 전용이며 회계사 PC에는 설치·배포되지 않는다.

**실제 클라이언트 데이터**: 이 저장소·개발 과정에는 실제 피감사인 수치가 들어가지
않는다. 검증 샘플은 DART에 이미 공개된 감사보고서만 쓴다.
