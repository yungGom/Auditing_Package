# DSD Footing 자동화 도구 — 인수인계

## 목적
DART 감사보고서 PDF의 표시 수치 상호 정합성(풋팅)을 자동 검증하고,
원본 지면에 틱마크를 오버레이한 PDF와 예외 색인 엑셀을 산출한다.

## 절대 제약
- **완전 오프라인.** 외부 API·웹훅·클라우드 연동 코드 금지. pip 로컬 설치만 허용.
- **실제 클라이언트 수치는 저장소·AI 컨텍스트에 반입 금지.** 검증용 샘플은 DART 공개 공시본만.
- **자동은 추천, 확정은 회계사.** 모든 산출물에 "candidate only" 명시.
- **미매칭 ≠ 0.** 검증 불가 항목은 반드시 `?`(SKIP)로 표시. 침묵 탈락 금지.
- **파일 반입은 diff만.** 외부 세션 사본(.py 전체 파일)을 저장소에 덮어쓰지 말 것 —
  2026-08-09 core.py가 구버전 사본으로 덮여 수정이 유실된 사고. 참고용 전체 파일은
  대조에만 쓴다. 반입 직후 `python intake_check.py`(시그니처 가드) 필수, pre-commit
  훅이 커밋 시 강제한다. handoff 류 사본 폴더는 커밋 금지(.gitignore).

## 스코프
- **범위 내:** 표시된 수치들 사이의 정합성 (표 내부 산술, 본표 간 연계, 주석번호 참조)
- **범위 밖:** 원장·조서 대사, 연결재무제표 비지배지분, 이상치 탐지, 증감률 분석
- 별도재무제표 기준. `연결`/`비지배지분` 감지 시 요약 시트에 플래그.

## 회귀 기준 (GATES 시드용 실측치)
샘플 = 삼성전자 FY25 별도 감사보고서(DART 공개본), 허용오차 0
```
A_total=345  A_OK=325  A_ROUND=0  A_DIFF=0  A_SKIP=20  A_SIGN=0
B_total=28   B_OK=24   B_DIFF=0   B_SKIP=4
C_link=51    C_unlink=56  C_diff=0
C7_gap=[]    C7_missing=[]   C7_unref=7
F1_단위누락=0  F2_표현불일치=3  F3_라벨불일치=9  F4_다중공백=4
D_para=229   D_flag=1
consolidated=False   nounit_pages=44
```
**이 수치는 위 샘플·tol=0 조합에서만 유효하다.** 다른 PDF나 tol에서는 대조하지 말 것.
등록 축 전체 4개(삼성·LGES·조선내화·휴맥스 — 각 축의 단위 구조·DIFF/SKIP 분류 메모 포함)는
GATES.json이 원본이다. 로직 변경 시 4축 전부 재측정할 것.

```
run_gates.py   회귀 게이트 진입점 (GATES.json 4축 자동 대조)

  ui/glyph_offsets.json  글리프 위치의 단일 출처 — glyph_gate.py가 render.py에 묶어둔다

tools/         보조 스크립트 — harden_webview2.ps1(선택, 기본 배포 미포함)
```

실행: `python foot.py <보고서.pdf>` (또는 run.bat에 PDF 드래그)
  옵션: `--tol 0` `--round-steps 1` `--min-won 100000000` `--out <폴더>` `--quiet`
        `--terms terms.csv` (F2 기준 표현 지정 — 샘플: terms_sample.csv, 미지정 시 빈도 기준)
  산출물: 입력 PDF 폴더에 `<원본이름>_틱마크.pdf` / `<원본이름>_예외색인.xlsx`
  구형 `python final.py <보고서.pdf> <허용오차>` 형태도 계속 동작.
  run.bat은 ASCII 전용 유지 — 배치 내 한글은 콘솔 코드페이지에 따라 깨진다.

marks.json은 v2(`dsd-footing-marks/2`)다 — `document`(제목·목차·counts) +
`marks`(검토 항목) + `annotations`(그리기 표시) + `page_notes`. L2 결과는 회사 사전이
그 문서에 적용될 때 `final.py`가 자동 편입한다(`level:"L2"`, 그룹 1건 + counterparts).
사전이 적용되지 않는 문서는 L2를 아예 돌리지 않아 실행시간·산출물이 종전과 같다.

L2 표간대사(단독 진단용, 사전 튜닝 시): `python l2_probe.py <보고서.pdf>`
  `--company <이름>` (기본: 파일명 `[회사명]...` 자동 추출) `--out <폴더>` `--quiet`
  산출물: `<원본>_L2대사.xlsx`(CONFIRMED/UNDECLARED/EXCLUDED/UNMAPPED/WARNINGS) +
  UNDECLARED 있으면 `<원본>_undeclared_suggestions.json`(assert_equal 붙여넣기용).
  회사 사전(`labels/{회사}.json`)의 `applies_to`가 파일명과 완전일치해야 적용된다 —
  scope가 그 문서 하나의 주석 번호 배치에 묶여 있어서다(설계안_L2_표간대사.md 9-4절).

편집 후 재렌더(분석 재실행 없음, Phase 1): `python render.py <보고서.pdf> --marks <원본>_marks.json`
  옵션: `--pages 12,13` (해당 페이지만 재렌더 후 기존 틱마크 PDF에 병합) `--out` `--quiet`
  marks.json에서 마크의 `status`를 `"removed"`로 바꾸면 그 마크만 지면에서 빠진다.

UI 셸(U-1, 오버레이 표시만 — marks.json 읽기·좌측 목록·판단 버튼은 다음 단계):
  `python ui/app.py <틱마크.pdf>` (foot.py가 만든 오버레이 PDF를 그대로 연다)
  개발 시 실제 창(WebView2)에 Playwright로 붙으려면(README.md "개발 도구" 참고):
  `set WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9222` 후 실행,
  `playwright.chromium.connect_over_cdp("http://127.0.0.1:9222")`로 연결.
  배포본에는 이 환경변수를 넣지 않는다.

## 현재 성능 (삼성전자 FY25 별도, 120p)
```

                DIFF 0 — 17건 전부 해소 (아래 분류 결과 참조)
                SKIP 20 = A3 분할 미완결 4 + 시간·인원 16 (p38 세후 표 2건은
                역방향 역산이 정확 검증해 OK 전환)
                판정 체계: OK/ROUND(표 단위 1스텝 반올림)/DIFF/SKIP(?)/SIGN(부호
                규약 상이 — 지면 ?, 색인 '부호규약' 태그. 절대값 불일치는 DIFF 유지)

D 줄글          → 검토완료(/) 229문단 / 표기 지적 1건 (오탐 0), '반품율' → '반품률'
하위항목 인식   → 28건 (접두 16 / 들여쓰기 12) — 들여쓰기 경로는 오탐 소지, 로그로 감시
```

## 설계 결정 (되돌리지 말 것)

1. **격자 추출(`extract_tables`)이 단일 진입점.** x1 좌표 하드코딩·클러스터 학습은
   폐기됨(주석 표에서 전부 실패). DSD PDF는 괘선이 있어 격자가 정확히 나온다.
2. **OCR 사용 안 함.** DART PDF는 iText 생성 벡터 텍스트라 텍스트 레이어가 100% 온전.
   OCR은 조용히 틀리므로 감사 증거로 부적합.
3. **주 산출물은 틱마크 PDF, 엑셀은 예외 색인 보조.**
   회계사가 보는 관점 = 원본 지면. 엑셀만 주면 표 경계가 사람 인식과 어긋난다.
4. **판정 단위는 표가 아니라 합계행.** 표 경계 판단을 도구가 하지 않게 하기 위함.
5. **마크 색상은 빨강 단일.** 감사조서 빨간펜 관행. 구분은 색이 아니라 모양으로
   **마크 정의(고정): 체크=산술 일치, X=차이 또는 표기 지적, ?=미검증,
   `/`=줄글 문단 검토 완료, 동그라미=레퍼 성립(본표측),
   `/BS`·`/CF`·`, FN6`=레퍼 성립(주석측, 상대 위치 표기).**
   **동그라미는 금액이 아니라 본표 주석열의 개별 주석번호에 친다.**
   한 행이 `4, 5, 7, 28`을 참조할 때 실제로 금액이 발견된 주석에만 원을 치므로,
   어느 주석에서 레퍼가 성립했고 어느 주석이 미확인인지 지면에서 바로 읽힌다.
   금액에 원을 치면 이 정보가 사라진다 — 되돌리지 말 것. `/`는 수기 조서에서 문단을 읽고 확인했다는 표시이며
   오류 표시가 아니다. 이 의미를 뒤집지 말 것.
6. **맞춤법은 규칙 기반만.** hanspell 등은 외부 API 호출이라 사용 금지.
   정밀도 우선 — 애매하면 지적하지 않는다. 오탐이 나면 도구 신뢰도가 무너진다.
7. **재무제표 유형별 규칙 분리** (`statements.APPLY`).
   손익계산서는 가감구조라 A3 적용 시 전량 오탐. IS/CI는 A5만.
8. **A2 성분열 완화는 ON 유지. 이중 합계열 성분범위 한정(과제5)과 함께여야 유효.**
   완화 단독으로는 이중 합계열 결함을 증폭시킨다(LGES p61/62 58→72 사례).
   범위 한정 적용 후 ON/OFF 재측정 결과 ON이 양방향 우세: OFF면 삼성 희소열
   오탐 3건 부활 + p87 표1 커버리지 3건 침묵 소실, LGES p24/25 오탐 2건 부활.
   가로합은 성분 열이 빠지면 조용히 틀리므로 배제가 안전한 방향이 아니다 (2026-08-09 확정).
9. **제외 트리거는 헤더 열 구성으로 판정한다. 데이터 행 라벨로 판정하지 않는다.**
   (EXCL_LABEL 폐지·재작성표 헤더 신호·요약 재무현황 헤더 신호가 이 원칙의 적용례)
   **명시적 예외 — % 행 A2 제외 (2026-08-09):** 주 신호(행의 전 값이 콤마 없는
   |v|<=100) + 보조 신호(라벨에 률·율·비율·%)의 AND. 데이터 행 라벨을 쓰는 이유:
   값 범위만으로는 소액 금액과 비율이 구분되지 않음 — 백만원 단위에서 2~99는 실제
   금액이며, 주 신호 단독은 LGES 특수관계자 표 OK 9건을 깎는 것이 4축 측정으로
   확인됨. 이 예외를 원칙 위반으로 보고 되돌리지 말 것.
10. **C 대사 소액 제외는 원 환산 절대금액, 기본 1억원(`refmap.MIN_WON`).** 표시 숫자
   기준은 단위에 따라 100만 배 다르게 작동한다. 4축 측정 (성립/미성립):
   | min_won | 삼성(백만원) | LGES(백만원) | 조선내화(천원) | 휴맥스(원/천원) |
   |---|---|---|---|---|
   | 1억 | 51/56 | 82/33 | 35/45 | 67/15 |
   | 10억 | 51/56 | 81/23 | 32/33 | 62/11 |
   1억에서도 삼성 불변 = 방어선을 낮춰도 기존 축 우연일치가 늘지 않음. 1억은 미성립을
   더 노출하는 보수적 방향(미성립 = 오류가 아니라 확인 대상) (2026-08-09 확정).
11. **마크는 픽셀이 아니라 데이터, 렌더러는 하나뿐이다 (Phase 1, 2026-08-14).**
    판정(`final.py`)이 그리는 대신 `marks.py`가 직렬화하는 `<원본>_marks.json`에
    담고, 실제로 그리는 곳은 `render.py` 하나뿐이다. 미리보기(향후 UI)와 출력이
    같은 렌더러를 쓰게 하기 위함 — 렌더러가 둘이면 좌표가 1pt만 어긋나도 화면과
    출력물이 달라진다. 좌표는 pdfplumber 규약(좌상단 원점)으로 저장하고, reportlab
    하단 원점 변환은 render.py가 전담한다. 도구 마크는 삭제하지 않고
    `status: "removed"`로 바꾼다 — marks.json이 조서 첨부물(제안 vs 확정 이력)이다.
    상세 설계는 `handoff/PHASE1_판정렌더분리.md`.

    **R-1(바이트 동등) 재현 시 함정 — 다음에 또 안 걸리려면:**
    - **좌표를 반올림하지 않는다.** `marks.py`의 `box4()`에서 소수 반올림을 넣으면
      reportlab이 원래 값과 다르게 텍스트 포맷해 바이트가 어긋난다(실측: 소수 2자리
      반올림 시 삼성 114페이지 전부 불일치). 분석이 낸 좌표를 그대로 흘릴 것.
    - **버전/시각 스탬프는 비교 전에 양쪽을 고정한다.** VER(git 커밋)·RUN_TS(실행
      시각)는 매 실행마다 달라지는 게 정상이라, 고정 없이 두 실행을 비교하면 그
      스탬프 문구 하나 때문에 무조건 불일치가 난다 — "스탬프는 원래 다르니 통과로
      치자"로 넘기면 실제 드로잉 바이트가 같은지를 영영 못 본다. `render_gate.py`가
      이미 고정 처리한다(VER="RGATE", RUN_TS 고정, `subprocess.run`/`datetime.now`
      monkeypatch).
    - **Canvas(invariant=1)는 비교 양쪽 모두 필수.** reportlab 기본값은 타임스탬프·
      문서ID가 매번 달라 같은 입력이어도 바이트가 다르다.
    - **부분 렌더 시 출력 경로를 읽기·쓰기 양쪽에 동시에 쓰지 않는다.**
      `render.render_all()`의 `existing_out`이 `out_path`와 같은 파일일 때
      `PdfReader`를 지연 로딩 상태로 열어두면, 같은 경로를 쓰기 모드로 여는 순간
      원본이 잘려 페이지가 빈 채로 읽힌다(실측: R-3 부분 렌더 테스트에서 병합 페이지의
      콘텐츠 스트림이 통째로 사라짐). 쓰기 시작 전에 `BytesIO`로 전량 버퍼링해
      파일 핸들과 분리해야 한다 — 이미 반영됨, 되돌리지 말 것.

    **회귀 게이트**: `python render_gate.py`(등록 4축, 페이지별 오버레이 SHA256을
    `RENDER_GATES.json`과 대조) — 판정/렌더 관련 코드를 고칠 때마다 돌릴 것.
    `--update`로 갱신. 되돌아갈 "Phase 1 이전 코드"가 이제 없으므로(대체됨), 이 게이트는
    레거시와의 비교가 아니라 저장된 골든 레퍼런스와의 일치·자기 결정성 확인이다.

12. **marks.json v2 — 검토 항목과 그리기 표시를 나눈다 (2026-08-25).**
    `marks[]`는 회계사가 판단하는 검토 항목(cross·question)만, `annotations[]`는
    지면에 그려지기만 하는 표시(tick·slash·circle·reftag·gapx)다. 실측 조선내화 반기
    307건 중 검토 항목은 8건뿐이라, 한 배열에 두면 화면 카운터가 조용히 307로
    부푼다(게이트가 못 잡는 실패 방향). 렌더러는 `marks.drawables()`로 둘을 합쳐
    `seq` 순으로 재생하므로 **배열이 나뉘어도 그리기 순서는 seq가 지킨다.**
    - **`render_gate.py`도 둘을 합쳐 세야 한다.** 안 그러면 배열 분리만으로
      `total_marks`가 307→8로 떨어져 가짜 불일치가 난다 — 스키마 변경을 드로잉
      변경으로 오독하게 만드는 함정이다.
    - 좌표는 `box`(pdfplumber 원본, 렌더러 전용)와 `bbox`([x,y,w,h], 화면 전용)를
      **병기**한다. `bbox`로 교체하면 뺄셈·복원 과정에서 부동소수 오차가 생겨 R-1을
      정면으로 건드린다 — 중복 저장이 훨씬 싸다.
    - 렌더 조건은 `status != "removed"`다(`pending`·`approved` 모두 그린다). 회계사가
      승인했다고 마크가 지면에서 사라지면 조서가 아니다.
    - **`operands`는 마크 id가 아니라 좌표 배열이다.** 합계에 들어간 성분 행에는 마크가
      없고(판정은 합계행에서만 난다), 성분마다 마크를 만들면 새 드로잉이라 R-1이
      확실히 깨진다. 지면 하이라이트는 pdf.js 오버레이지 틱마크가 아니므로 좌표면 된다.
    - 미검증 사유는 `core.SKIP_REASON_TEXT`(코드→한국어 문장)로 실어 보낸다.
      **판정값 `n`은 바꾸지 않는다** — 사유는 라벨일 뿐이다. 매핑에 없는 코드는
      `UNRESOLVED_REASON(코드)`로 노출한다(빈 문자열 금지).
    상세는 `설계안_marks_스키마_v2.md`.

13. **지면 레퍼 태그 `/SCE` → `/CE` (2026-08-25, 의도적 드로잉 변경).**
    회계사 실무 표기·화면(rev.2)과 통일. `refmap.STMT_TAG`에서 SCE→"CE" 한 글자
    변경 — R-1이 깨지는 게 정상이라 순서를 지켜 처리했다: 변경 전 게이트 통과 확인 →
    변경 → 재실행해 **변경과 무관한 페이지에서 불일치가 없는지 확인**(삼성전자
    p67, 주석20의 SCE 레퍼 1곳뿐 — 마크 수 697→697 불변) → 그 뒤에만 `--update`로
    골든 재기록. GATES 24지표는 4축 전부 무변화(판정 로직 비접촉이므로 당연한 결과지만
    "당연하니 생략"하지 않고 실측했다). 지면 문자열을 바꾸는 모든 향후 변경은 이
    순서(사전 확인 → 변경 → 국소성 확인 → 사후 갱신)를 그대로 따를 것 — 먼저
    `--update`부터 돌리면 그림이 바뀌었는지 자체를 못 본다(결정 11의 함정과 동일).

14. **PyWebView `url=`에 맨 경로를 주면 로컬 서버가 자동으로 뜬다 (2026-08-26, UI 셸
    U-1 실측 함정).** `webview.create_window(url=경로)`처럼 `file://`/`http://`
    접두어 없는 문자열을 주면 pywebview가 `is_local_url()`에 걸려 **bottle 기반
    로컬 서버를 자동으로 띄운다**(포트가 LISTENING으로 열리는 것을 netstat으로
    실측). "서버를 안 띄운다"는 설계 결정을 이 함정 하나가 조용히 깬다 — 반드시
    `url="file:///" + 절대경로.replace(os.sep, "/")` 형태로 **명시적 file:// URL**을
    줘야 한다. js_api 브리지는 file:// 모드에서도 WebView2의 네이티브
    `postMessage`(Windows) 경로를 타므로 그대로 동작한다 — 서버가 필요한 건 자산
    서빙 쪽이지 브리지 쪽이 아니다. 다음에 PyWebView 창을 새로 띄울 때 이 함정을
    또 밟지 말 것 — `ui/app.py`의 주석 참고.

15. **이 개발 환경에서 CDP 스크린샷 자동화가 안 된다 (2026-08-26, U-1 실측).**
    Playwright로 실제 PyWebView 창(WebView2)에 CDP 접속(`connect_over_cdp`)하는
    것 자체는 즉시 되고, DOM 조회(`page.evaluate`)·클릭·입력도 정상 동작한다.
    다만 `page.screenshot()`/raw CDP `Page.captureScreenshot` 둘 다 응답 없이
    멈춘다 — 이 세션의 Windows 데스크톱에 실제 화면 합성(compositor)이 없어
    창이 실제로 페인트되지 않는 것으로 추정(원격/자동화 세션의 환경 제약이지
    코드 버그가 아니다). U-1은 이 때문에 게이트 2·3(시각적 정확성)을 **사람이
    실제 창을 보고 육안으로 확인**하는 방식으로 통과시켰다 — 자동 스크린샷
    비교가 아니다.
    **다음 UI 단계에서 참고할 것**: DOM 상태·값 조회(요소 존재, 텍스트 내용,
    카운트, 클릭 후 상태 변화 등)는 CDP `Runtime.evaluate`/Playwright locator로
    **자동 검증 가능** — 계속 이 경로를 쓸 것. 픽셀 단위 렌더링(마크 위치·색상·
    폰트 정확도 등 눈으로만 판단 가능한 것)은 매 단계 사람에게 체크리스트로
    넘길 것. 이 환경 제약이 나중에 풀리면(실제 디스플레이가 붙은 세션 등)
    스크린샷 자동 비교를 다시 시도해 볼 것 — 안 되는 게 영구적이라고 단정하지
    않는다.

## 네트워크·오프라인 범위 — "완전 오프라인"의 정의 (2026-08-26)

이 문서 전체가 "완전 오프라인"을 절대 규칙으로 쓴다. UI 셸(PyWebView) 착수 후
그 정의를 명확히 할 필요가 실측으로 드러났다 — WebView2(Windows 내장 Chromium
엔진) 자체가 백그라운드로 외부 접속을 하는 것이 4회 실행 중 2회 관측됐다.
**"완전 오프라인"은 "이 저장소가 작성한 코드가 외부와 통신하지 않는다"는 뜻이다.**
Windows 시스템 컴포넌트(WebView2 런타임)의 자체 동작까지 도구가 통제할 수는
없다 — audit_toolbox의 EasyOCR 최초 1회 모델 다운로드 허용과 같은 성격의 구분이다.

| | 우리 도구(DSD_footing 코드) | WebView2 런타임(Windows 시스템 컴포넌트) |
|---|---|---|
| 무엇이 나가는가 | **없음** — fetch/XHR 호출 0건(`ui/web/viewer.js` 전체에 없음) | 런타임 버전 정보(컴포넌트 업데이트 체크 추정) — 감사 데이터 아님 |
| 포트 | **0개** — `ui/app.py`는 `file://` URL로 직접 로드, 로컬 서버 안 띄움(위 결정 14) | 없음 (아웃바운드 HTTPS만, netstat엔 ESTABLISHED로만 보임) |
| PDF 로딩 | JS 브리지(`window.pywebview.api.get_pdf()`) — 프로세스 내 호출, HTTP 아님 | 관여 없음 |
| 확인 방법 | `netstat -ano \| findstr LISTENING` 에서 우리 python.exe/msedgewebview2.exe 자식 프로세스가 리스닝 포트를 안 여는지 대조(PID→프로세스명은 작업 관리자 "세부 정보" 탭) | `netstat -ano \| findstr ":443"` 에서 msedgewebview2.exe PID의 ESTABLISHED 접속 유무 |
| 끄고 싶다면 | 해당 없음(원래 안 함) | `tools/harden_webview2.ps1`(선택, 기본 배포 미포함) — Edge/Office/탐색기가 이미 하는 것과 같은 시스템 업데이트 체크를 IT 정책으로 차단 |

같은 표를 README.md(배포용, IT팀 질의 대응용)에도 둔다 — 두 문서가 어긋나면
안 되므로 내용을 고칠 때 항상 같이 갱신할 것.

16. **화면 카운터 — "document.counts에서" vs "marks[]를 세서"의 경계선
    (2026-08-27, U-2 설계 확정).** 처음엔 "배열을 세지 마라"로만 지시했다가
    실제로 막혔다 — `document.counts`(diff/unverified/ok/recon/prose/typo)는
    분석 시점에 확정된 총계라 화면에서 다시 세면 안 되지만, `status`(pending/
    approved/removed)는 회계사가 판단할 때마다 바뀌는 **런타임 상태**라
    `marks.py`가 애초에 만들 수 없는 값이다(분석 시점엔 전부 pending이라
    의미도 없음). 규칙을 이렇게 가른다:
    - **전체 건수**(총 몇 건인가) → 반드시 `document.counts`에서 읽는다.
      배열 길이를 다시 세지 않는다 — 성능·불일치 방지가 목적.
    - **진행 상태 집계**(미검토 몇 건, 검토 완료 몇 건 등 status 기반) →
      로드된 `marks[]`를 그 자리에서 센다 — 애초에 다른 소스가 없다.
    다음에 카운터 종류가 늘어나도 이 기준으로 가른다. "배열을 세지 마라"를
    문자 그대로 전체에 적용하면 존재하지 않는 값을 읽으려는 버그가 난다.

17. **`table_label` 미확인 표시("표 이름 미확인")는 4축 실데이터로 재현되지

    연차 12 / 휴맥스 36건.

18. **보이는 마크(✗ / ?)는 `box` 밖에 그려진다 — UI 히트영역은 글리프 기준이어야
    한다 (2026-08-27, U-4 실측).** 오버레이 콘텐츠 스트림에서 직접 잰 결과
    (조선내화 반기 p8 `cross:A5:p8:t1:r12:c2`): `box.x1 = 316.260`인데 글리프는
    `314.760 ~ 321.260` — **6.5pt 중 5.0pt(77%)가 셀 오른쪽 바깥**이다.
    `box`만 히트영역으로 쓰면 회계사가 눈에 보이는 ✗를 클릭했을 때 대부분
    빗나간다. 반대로 `box ∪ 글리프`를 평평하게 합치면 겹침이 4쌍 → 54쌍으로
    폭증해(5축 실측) 후보 목록이 상시로 뜬다. 그래서 **2단 우선순위**를 쓴다:
    `tier1 = 글리프(최소 12pt)` → 여기서 잡히면 끝, 비면 `tier2 = 셀 box`.
    - **게이트가 사용자 행동을 재야 한다**: "box 중심점을 클릭" 게이트는 이 결함을
      무조건 통과시킨다(중심은 당연히 box 안이다). `글리프 중심 클릭` 게이트를
      반드시 함께 돌릴 것 — 실질 검증은 그쪽이다.
    - **`ui/glyph_offsets.json`이 글리프 위치의 유일한 출처**이고,
      `python glyph_gate.py`가 그 값으로 계산한 좌표를 `render.draw_mark()`가
      **실제로 그린** 좌표와 마크 전건에서 대조한다(상수 문자열 비교가 아니라
      기록용 캔버스로 render.py를 진짜 호출해 좌표를 받는다). 0.1pt만 어긋나도
      잡히는 것을 음성 테스트로 확인했다. **`render.py`의 드로잉 오프셋을 고치면
      이 JSON도 같이 고쳐야 하고, 안 고치면 이 게이트가 잡는다** — UI가 조용히
      어긋나는 것을 막는 유일한 장치다.

    U-6에 필요하다는 것을 사용자가 명시적으로 지적했다. U-5는 데이터만 쌓는다.

## 침묵 미검증 원인 (오탐보다 위험 — 검증 후보가 생성조차 안 되는 유형)
오탐은 지면에 X로 보이지만, 침묵 미검증은 아무 표시가 없어 실제 풋팅 오류가
무표시로 통과한다 ("미매칭 ≠ 0" 위반). 발견 즉시 이 절에 등재할 것.

**패턴 교훈 — 기준선이 통과한다고 그 경로가 옳다는 뜻이 아니다.** 운 좋게 정직한
실패(SKIP)로 떨어졌을 뿐일 수 있다. 기준선 축의 결함을 다른 축이 노출시킨 사례 3건:
① 총계행 스택 미정산 — 삼성은 자본 항목 depth가 우연히 같아 pop됨, LGES가 노출
② 라벨 열 c0 고정 — 삼성 특수관계자 표는 침묵 미검증으로 가려짐, 조선내화가 노출
③ 분할 표 마지막 행 부모 오판 — 삼성 p10 I.자본금은 acc<2로 우연히 SKIP, 휴맥스
   p8(충당부채 뒤 항목 존재)이 DIFF로 노출. 새 축을 붙일 때마다 "기준선의 같은 구조가
   왜 통과했는가"를 물을 것 — 답이 '우연'이면 기준선 쪽도 결함이다.
- **라벨 열 c0 고정 가정** (해결: 첫 금액열 왼쪽 첫 TEXT 셀로 행 단위 판정) —
  구분류가 c0(병합·희소), 계정·계가 c1인 조판에서 c1의 `계`·`소 계`가 전혀 안 보였다.

  53건이 침묵 미검증**이었음이 드러난 사례 (커버리지 280→345, 판정 변화 0 전수 입증).

  "이 표에서 검증이 몇 건 나와야 정상인가"를 물을 것

- **헤더 반복형 분할 표 (잠복 — 탐지기로 감시 중)**: 매 페이지 헤더를 반복하는 다페이지
  분할 표는 h0=1이라 carry 병합이 차단된다. 삼성 p91~101 종속기업 현황표(11페이지,

## 남은 과제
- **L2 `applies_to`는 임시방편이다 (2026-08-25 조건부 승인)** — 회사 사전
  (`labels/{회사}.json`)의 scope는 사실 "회사"가 아니라 "그 문서 하나의 주석
  번호 배치"에 묶여 있다. 지금은 파일명 완전일치(`applies_to`)로 오적용을
  막지만, 파일명이 조금만 바뀌어도(괄호 번호·공백 차이) 사전이 통째로 안 걸려
  UNMAPPED만 폭증하고 회계사는 이유를 알기 어렵다 — `l2_probe.py`가 콘솔·xlsx
  최상단에 경고를 띄우는 것으로 임시 보완했다. 정식 해법은 설계안 원안의
  `table_aliases`+`fingerprint`(TABLE_SHIFT) — 다음 회사 사전을 추가할 때
  이 방식으로 정식 승격할 것.
- **`marks.json`에 `glyph_bbox`를 직접 실어 `glyph_gate.py`를 없앨 것** — 지금은
  `render.py`의 글리프 드로잉 오프셋을 `ui/glyph_offsets.json`이 복제하고 그
  복제본을 게이트가 render.py에 묶어두는 구조다(결정 18). `marks.py`가 판정
  시점에 글리프 사각형까지 내보내면 복제도 게이트도 필요 없어진다. U-4에서
  하지 않은 이유: marks.json 스키마 변경 + R-1 골든 재갱신이 걸려, 좌표 매칭과
  스키마 변경을 병행하면 원인 분리가 안 된다(Phase 1에서 같은 이유로 병행 금지).

## 레퍼 대사(refmap) 설계 메모
- **탐색 범위를 주석번호로 한정한다.** 본표 각 행은 이미 주석열에 참조번호를 갖고 있으므로,
  전체 문서에서 같은 금액을 찾지 않고 해당 주석 페이지 구간 안에서만 찾는다.
  이것이 우연일치 오탐을 막는 핵심 장치다.
- **주석 페이지 구간은 겹치지 않게 끊는다** (`end = 다음주석 시작 - 1`).
  한 페이지가 두 주석에 걸치면 엉뚱한 `FN` 태그가 붙는다.
- **절대값 1,000 미만은 대사 대상에서 제외.** 소액·비율·주식수는 우연일치 위험이 크다.
- **주석간 레퍼(`, FN6`)는 상대 주석에서도 `계`/`합계` 행일 때만 인정.**
- 미성립은 오류가 아니라 "주석에 동일 금액이 그대로 없음"이다. 회계사 확인 대상으로만 넘긴다.
