# DSD Footing 자동화 도구 — 인수인계

## 목적
DART 감사보고서 PDF의 표시 수치 상호 정합성(풋팅)을 자동 검증하고,
원본 지면에 틱마크를 오버레이한 PDF와 예외 색인 엑셀을 산출한다.

## 절대 제약
- **완전 오프라인.** 외부 API·웹훅·클라우드 연동 코드 금지. pip 로컬 설치만 허용.
- **실제 클라이언트 수치는 저장소·AI 컨텍스트에 반입 금지.** 검증용 샘플은 DART 공개 공시본만.
- **자동은 추천, 확정은 회계사.** 모든 산출물에 "candidate only" 명시.
- **미매칭 ≠ 0.** 검증 불가 항목은 반드시 `?`(SKIP)로 표시. 침묵 탈락 금지.
- **파일 반입은 diff만.** 외부 세션 사본(.py 전체 파일)을 저장소에 덮어쓰지 말 것 —
  2026-08-09 core.py가 구버전 사본으로 덮여 수정이 유실된 사고. 참고용 전체 파일은
  대조에만 쓴다. 반입 직후 `python intake_check.py`(시그니처 가드) 필수, pre-commit
  훅이 커밋 시 강제한다. handoff 류 사본 폴더는 커밋 금지(.gitignore).

## 스코프
- **범위 내:** 표시된 수치들 사이의 정합성 (표 내부 산술, 본표 간 연계, 주석번호 참조)
- **범위 밖:** 원장·조서 대사, 연결재무제표 비지배지분, 이상치 탐지, 증감률 분석
- 별도재무제표 기준. `연결`/`비지배지분` 감지 시 요약 시트에 플래그.

## 파일 구조
```
core.py        값 파싱, 격자 분석, A1/A2, 단위, 판정
statements.py  본표 전용 — 라벨 계층, A3, A5, 재무제표 유형 판정
tieout.py      B1~B10 본표 간 연계
notes.py       C7 주석번호 정합성
refmap.py      C1~C6 본표↔주석 레퍼 대사
prose.py       줄글 표기 검토 (규칙 기반, 오프라인)
consist.py     F1~F4 문서 전체 일관성
final.py       통합 실행 → 틱마크 PDF + 예외색인 엑셀
```

실행: `python final.py <보고서.pdf> <허용오차>`

## 현재 성능 (삼성전자 FY25 별도, 120p)
```
A 산술  280건 → OK 270 (96.4%) / DIFF 0 / SKIP 10
                DIFF 0 — 17건 전부 해소 (아래 분류 결과 참조)
                SKIP 10 = A3 빈행 4 + 적용부적합 제외 6 (p38 법인세효과, p119 시간·인원)
                총건수 277→280: A2 성분열 완화로 p87 표1(침묵 미검증이던 표) 3행 신규 검증(전부 OK)
B 연계   28건 → OK  24         / 차이 0  / 미검증 4
C 레퍼         → 성립 51 / 미성립 56 (본표 주석참조 107건 기준)
C7 주석       → 결번 없음, 참조무주석 없음
F 일관성       → 단위누락 0 / 표현불일치 3그룹 / 라벨불일치 9 / 다중공백 4
D 줄글          → 검토완료(/) 229문단 / 표기 지적 1건 (오탐 0), '반품율' → '반품률'
하위항목 인식   → 28건 (접두 16 / 들여쓰기 12) — 들여쓰기 경로는 오탐 소지, 로그로 감시
```

## 설계 결정 (되돌리지 말 것)

1. **격자 추출(`extract_tables`)이 단일 진입점.** x1 좌표 하드코딩·클러스터 학습은
   폐기됨(주석 표에서 전부 실패). DSD PDF는 괘선이 있어 격자가 정확히 나온다.
2. **OCR 사용 안 함.** DART PDF는 iText 생성 벡터 텍스트라 텍스트 레이어가 100% 온전.
   OCR은 조용히 틀리므로 감사 증거로 부적합.
3. **주 산출물은 틱마크 PDF, 엑셀은 예외 색인 보조.**
   회계사가 보는 관점 = 원본 지면. 엑셀만 주면 표 경계가 사람 인식과 어긋난다.
4. **판정 단위는 표가 아니라 합계행.** 표 경계 판단을 도구가 하지 않게 하기 위함.
5. **마크 색상은 빨강 단일.** 감사조서 빨간펜 관행. 구분은 색이 아니라 모양으로
   **마크 정의(고정): 체크=산술 일치, X=차이 또는 표기 지적, ?=미검증,
   `/`=줄글 문단 검토 완료, 동그라미=레퍼 성립(본표측),
   `/BS`·`/CF`·`, FN6`=레퍼 성립(주석측, 상대 위치 표기).**
   **동그라미는 금액이 아니라 본표 주석열의 개별 주석번호에 친다.**
   한 행이 `4, 5, 7, 28`을 참조할 때 실제로 금액이 발견된 주석에만 원을 치므로,
   어느 주석에서 레퍼가 성립했고 어느 주석이 미확인인지 지면에서 바로 읽힌다.
   금액에 원을 치면 이 정보가 사라진다 — 되돌리지 말 것. `/`는 수기 조서에서 문단을 읽고 확인했다는 표시이며
   오류 표시가 아니다. 이 의미를 뒤집지 말 것.
6. **맞춤법은 규칙 기반만.** hanspell 등은 외부 API 호출이라 사용 금지.
   정밀도 우선 — 애매하면 지적하지 않는다. 오탐이 나면 도구 신뢰도가 무너진다.
7. **재무제표 유형별 규칙 분리** (`statements.APPLY`).
   손익계산서는 가감구조라 A3 적용 시 전량 오탐. IS/CI는 A5만.

## 알려진 오탐 원인 (해결 완료 — 재발 시 여기부터 확인)
- 주석번호 열을 금액열로 오인 → `core.is_note_col`
- 페이지 분할 표 → `final.py` carry 병합
- 소계/계 이중계상 → `core.check_table`의 `covered` 집합

- `APPLY.get(st, ())`에서 `None` 키가 존재하면 기본값이 무시됨

## DIFF 17건 분류 결과 (회계사 확인 완료, 2026-08 · **전 17건 해소 완료**)
**진성 오류 0건.** 전부 도구측 문제이며 이 보고서에 실제 풋팅 오류는 없음.

| 원인 | 건수 | 위치 | 조치 | 상태 |
|---|---|---|---|---|
| 소계 중복계상 | 6 | p71/72(4) p86(2) | 하위항목 구조 인식(접두·들여쓰기, n=1 허용) + 역산 검증(n≥2) | **해소 → OK** |
| 구간 경계 미인식 | 2 | p51(2) | ~~소계 중복계상~~ **정정: 콜론(`:`) 구간 라벨이 경계로 작동하지 않아 앞 구간 행이 다음 구간 계에 합산됨.** 소계로 마감되지 않은 '열린' 콜론 구간을 자유행 합산 경계로 추가 | **해소 → OK** |
| 적용 부적합 | 6 | p38(2) p119(4) | p38 법인세효과 반영표, p119 감사시간·인원 → 라벨 기반 제외 | **해소 → SKIP** |
| 희소 열 탈락 (가로합 오탐) | 3 | p34(2) p87(1) | ~~열 선택 오류~~ **정정: NUM 1개짜리 희소 열이 `numcols`(NUM≥2)에서 탈락해 가로합 성분 누락.** A2 전용 성분열 완화(NUM≥1·텍스트 無·주석열 아님) — A1/A3/A5의 numcols는 불변 | **해소 → OK** |

가로합 완화의 부수 효과: 같은 희소 열 현상으로 **표 전체가 침묵 미검증**이던 p87 표1이
3행 신규 검증됨(전부 OK, A_total 277→280). 가로합은 성분 열이 빠지면 조용히 틀리므로
배제가 안전한 방향이 아니다 — 세로합(그 열을 안 볼 뿐)과 위험 방향이 반대.

**소계 식별 3경로 (core.check_table, 병행):**
1. 접두 기호 — 라벨이 `-`·`‐`·`–`·`ㆍ`·`·`로 시작하면 바로 위 비하위 행에 귀속 (n=1 허용)
2. 들여쓰기 — 첫 열 라벨 x0를 표 단위 군집화, 가장 왼쪽 군집(기준선)보다 3pt 이상
   오른쪽이면 하위항목. 선행 공백도 병행. **오탐 소지 有 — 판정 로그(SUBLOG) 필수 확인**
3. 역산 검증 — 행 R = 바로 아래 연속 n개 행의 합(n≥2, 열별 |값|≥1000)이면 그 n개 행 covered

**콜론 경계 주의** — 소계로 마감된 콜론 구간(예: p41 `연체된 채권:` + 소 계)까지 경계로 쓰면
구간 앞의 정당한 합산 행이 잘려 검증이 소실된다(A_total 감소). '열린 구간'만 경계로 쓸 것.

## 남은 과제
- **B3 미검증** — 자본변동표 `Ⅰ.총포괄손익` 행이 빈 행이라 소계 미산출
- **A7 튜닝** — 현 샘플에 ROUND 0건. 천원 단위 보고서로 재시험 필요
- **C1~C6 주석↔본표 대사** — 회사별 매핑 템플릿(고정 입력) 방식으로 설계
- **줄글 규칙 확장** — 현 규칙은 고정밀 소수. 실전 오탈자 사례 축적 후 추가.
  율/률·열/렬은 종성 분해로 정확 판정(`prose.jong`). 같은 방식으로 이/리, 양/량 확장 가능
- **레퍼 미성립 56건 분류** — 본표 금액이 주석에 그대로 없는 정상 사례가 다수.
  주석에서 분해 표시되는 계정(기타유동자산, 순확정급여자산 등)은 부분합 대사 규칙 필요
- **A4 롤포워드** — 기초+증가-감소=기말. 부호 규칙 표 유형별 정의 필요
- **UI** — Claude Design으로 화면 설계 후 Streamlit/PyWebView 연결

## 레퍼 대사(refmap) 설계 메모
- **탐색 범위를 주석번호로 한정한다.** 본표 각 행은 이미 주석열에 참조번호를 갖고 있으므로,
  전체 문서에서 같은 금액을 찾지 않고 해당 주석 페이지 구간 안에서만 찾는다.
  이것이 우연일치 오탐을 막는 핵심 장치다.
- **주석 페이지 구간은 겹치지 않게 끊는다** (`end = 다음주석 시작 - 1`).
  한 페이지가 두 주석에 걸치면 엉뚱한 `FN` 태그가 붙는다.
- **절대값 1,000 미만은 대사 대상에서 제외.** 소액·비율·주식수는 우연일치 위험이 크다.
- **주석간 레퍼(`, FN6`)는 상대 주석에서도 `계`/`합계` 행일 때만 인정.**
- 미성립은 오류가 아니라 "주석에 동일 금액이 그대로 없음"이다. 회계사 확인 대상으로만 넘긴다.
