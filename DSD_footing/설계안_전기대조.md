# 설계안 — 전기 보고서 대조 (`--prior`) · 구현 금지, 승인 대기

> 상태: **설계안만. 착수 여부는 회계사 결정.** (2026-08-13)
> 원 요청("DART 공시로 완전성 보완")은 절대 제약(완전 오프라인·외부 API 금지) 위반이라
> 우회 설계로 대체한다. 감사 중 도구가 회사 공시를 자동 조회하면 접근 로그가 남아
> 실무상으로도 위험하다.

## 입력 방식 — 오프라인 우회

회계사가 DART에서 전기 감사보고서를 **수동 다운로드**해 로컬에 두고, 도구는 그 파일만 읽는다.

```
python foot.py 당기보고서.pdf --prior 전기보고서.pdf
```

`--prior` 미지정 시 현행 동작 그대로 (4축 게이트 무변화 원칙).

## 검증 항목 (우선순위 순)

### P1. 전기말 잔액 대사 — 가장 값이 큼
**B7(자본변동표 기초 = 전기말 자본총계)·B9(CF 기초현금 = 전기말 현금)가 4축 전부
미검증인 이유가 '설계상 전전기 필요'였다.** 전기 보고서가 들어오면:
- 당기 보고서의 '전기' 열 ↔ **전기 보고서의 '당기' 열** 대사 (⚠ 아래 시점 가드)
- B7·B9의 '전기' 측이 전기 보고서의 전전기… 아니라 전기 보고서 당기 열로 해소
- 본표 전 항목으로 확장 가능: 당기 BS 전기열 전체 ↔ 전기 BS 당기열 전체
  (AuditDesk '전기대사'와 같은 개념 — 여기서는 표시 수치끼리, PDF 기반)

### P2. 주석 항목 누락 플래그
전기 보고서의 주석 선언 목록(`notes.run`)과 당기 목록을 대조 — 전기에 있던 주석
제목이 당기에 없으면 '주석 누락 후보' 플래그 (오류 아님, 확인 대상 표시).

### P3. 표현 일관성 — 전기 표현을 기준으로
전기 보고서에서 F2 그룹별 사용 표현을 추출해 **`--terms` 기준으로 자동 사용**.
명시적 `--terms` 파일이 있으면 파일이 우선.

### P4. 계정과목 명칭 변경 감지
본표 라벨(key 정규화 후)을 전기·당기 비교 — 전기에만 있는 라벨 + 당기에만 있는
라벨 쌍에서 값이 일치하는 조합은 '명칭 변경 후보'로 표시.

## ⚠ 시점 가드 (필수 선행 설계)

전기 보고서의 '당기' 열 ↔ 당기 보고서의 '전기' 열 대사가 기본 구조인데,
**중간재무보고면 시점이 어긋난다**:
- 당기 반기보고서의 BS '전기' 열 = 직전 연차말 → 전기 **연차** 보고서와 대사 가능
- 그러나 IS/CI '전기' 열 = 전년 동기간 → 전기 연차 보고서와 대사 불가
- 기존 `tieout`의 interim 가드(전반기말 vs 전기말 시점 상이 → 미검증)와 같은 논리를
  문서 조합(연차↔연차 / 반기↔연차 / 반기↔전년 반기)별로 정의해야 한다.
- 판정 불가 조합은 **미검증으로 낸다** (가짜 차이 금지 — B10 안전장치와 같은 원칙).

## 산출물

- 예외색인에 `P_전기대사` 시트 신설: 항목·전기 보고서 값·당기 보고서 전기열 값·판정
- 게이트: `--prior` 지정 실행은 별도 지표(P_*)로, 기존 24지표와 분리
  (미지정 실행의 24지표는 불변이어야 한다)
