## 1. 모듈 구성

`l2_probe.py` 하나로 실행하되, 저장소 관행(core/statements/tieout/notes/refmap처럼
관심사 분리)대로 내부는 3개 파일로 나눈다 — 전부 `l2_probe.py`가 오케스트레이션.

```
l2_extract.py   PDF → (canonical_label, column_key, period_key, doc_key,
                        value, page, bbox, table_id) 튜플 목록 추출
l2_labels.py    labels/*.json 로드·검증(스키마·scope 강제) + 라벨 정규화 +
                 매칭 엔진(CONFIRMED/EXCLUDED/UNDECLARED 판정)
l2_probe.py     CLI 진입점 — extract → labels 매칭 → 콘솔 요약 + xlsx 저장
```

기존 코드 재사용(신규 로직 최소화):
- `core.grid_info` — 격자 분석 그대로
- `refmap.unit_texts` / `core.UNIT_MULT` — 표 귀속 단위, 원 환산 비교(C 대사와 동일 원칙)
- `notes.NOTE_HEAD` — 주석 선언 헤더 탐지 재사용, `table_id`의 주석번호 축에 사용
- `statements.stmt_type` — 본표 페이지 판정 재사용, `table_id`의 BS/IS/CI/CF/SCE 축에 사용
- `statements.key()` — 1차 라벨 정규화(계층기호·괄호주석 제거)의 전처리 단계로 재사용,
  그 위에 라벨 매핑 사전을 얹는다(아래 3절)

`period_axis`/`pick_period`(statements.py)는 **재사용하지 않는다** — 그건 BS/IS/CI/CF의
(세부,합계) 열쌍 구조를 전제하는데, 주석 표는 헤더 구조가 표마다 제각각이라 전제가
안 맞는다. L2는 별도의, 더 단순한 열 헤더 분류기를 둔다(2절).

## 2. period_key 판정

### 2-1. 신호 어휘 (statements.py와 같은 정규식 재사용)

```python
SIDE_CUR = re.compile(r"\(\s*당\s*\)|당\s*(?:기|반기|분기|회계연도)")
SIDE_PRV = re.compile(r"\(\s*전\s*\)|전\s*(?:기|반기|분기|회계연도)")
SPAN_3M  = re.compile(r"3\s*개\s*월|삼\s*개\s*월")
SPAN_CUM = re.compile(r"누\s*적")
POINT_END = re.compile(r"(반기|분기)?\s*기?\s*말")   # tieout.SCE_END에서 말 부분만 재사용
POINT_BEG = re.compile(r"(반기|분기)?\s*기?\s*초")   # tieout.SCE_BEG에서 초 부분만 재사용
```

### 2-2. 판정 순서 (컬럼 헤더 텍스트 1개 또는 병합 헤더 다중행 텍스트 1개에 대해)

```
1. side = 당/전 감지 (SIDE_CUR/SIDE_PRV). 둘 다 없거나 둘 다 있으면 판정 불가 → null
2. POINT_END 매치 → END (BS·SCE류 시점 잔액)
   POINT_BEG 매치 → 당이면 PY-END로 정규화(당기초 == 전기말, 회계상 항등),
                     전이면 미정의(PPY-END 슬롯 없음 → null, 잘못 묶기보다 배제)
3. 시점 마커 없으면 흐름(유량) 컬럼 — SPAN_3M → CY-3M/PY-3M, SPAN_CUM → CY-CUM/PY-CUM
4. 시점도 구간도 없이 '당기'/'전기'만 있으면(연차보고서 관행) → CY-CUM/PY-CUM 기본
   (흐름 항목의 '당기'는 사실상 누적 1건뿐이므로 CUM으로 취급 — 시점류 표는 이미
   3단계에서 END로 걸러졌으므로 여기 도달하지 않는다)
```

같은 열이 헤더 병합(다중 행)으로 나뉜 경우 `_fill_merged`(statements.py)와 동일한
방식으로 병합행을 좌→우 전파해 합친 텍스트에 위 순서를 적용한다.

### 2-3. SCE 행 라벨(열이 아니라 행에 시점이 실리는 경우)

자본변동표는 시점이 **행 라벨**에 있다("당기초"/"당기말" 등, 열은 자본항목).
이 경우 `column_key`가 자본항목명(예: "이익잉여금@c4")이 되고 `period_key`는 그 **행**
라벨에서 뽑는다 — tieout.SCE_END/SCE_BEG 판정을 그대로 가져와 동일 정규화(당기초→PY-END)
적용. row-period냐 col-period냐는 표 유형(SCE는 행, 나머지는 열)으로 고정 분기하며
자동 추론하지 않는다.

## 3. table_id

```
BS | IS | CI | CF | SCE                본표 (statements.stmt_type 그대로)
n{주석번호}-t{순번}                     주석 표 — 순번은 그 주석 페이지 구간
                                        (refmap.note_ranges 재사용) 안에서 등장 순서로
                                        1부터. 페이지 분할과 무관하게 안정적.
```

`refmap.note_ranges(pdf)`가 이미 "주석번호 → (시작p, 끝p)" 를 낸다 — 그 구간 안의
`page.find_tables()` 결과를 페이지 순·표 순으로 순회하며 t1,t2,... 부여.

한 주석에 표가 여러 개(정답셋 10번 "주석9(2)에 표가 둘")여도 `n9-t2`처럼 그냥 순번만
붙는다. "(1)"/"(2)" 같은 프로즈 하위번호는 자동 인식하지 않는다(자동 라벨 매칭 금지
원칙과 동일선상) — 사람이 `table_aliases`에서 읽기 쉬운 이름으로 부른다.

## 4. JSON 스키마

의존성 추가 없음 — 표준 라이브러리 `json`만 사용.

### 4-1. `labels/_common.json`

```jsonc
{
  "schema": "dsd-l2-labels/1",
  "labels": {
    // canonical_label: { aliases: [원문 표기들], scope: null | "표식별자 or 자유문자열" }
    // scope 없는 항목만 여기(전 회사 공통) 허용 — 회사 독립적인 고유명사성 라벨만.
    "이익잉여금": { "aliases": ["이익잉여금", "결손금", "미처리결손금"] },
    "지분법손익": { "aliases": ["지분법손익", "지분법이익", "지분법손실",
                               "관계기업및공동기업투자손익"] }
  }
}
```

### 4-2. `labels/{회사}.json` (예: `labels/조선내화.json`)

```jsonc
{
  "schema": "dsd-l2-labels/1",
  "extends": "_common",

  "overrides": {
    // 회사별 라벨 정의 — _common과 같은 canonical_label을 다시 쓰면 별칭을 덮어씀.
    // ★ 범용어(합계/기초/기말/소계 등, GENERIC_TERMS 하드코딩 목록)는 scope 필수 —
    //   없으면 l2_labels.load()가 즉시 예외로 로드를 거부한다(런타임 무시 아님).
    "감가상각비[판관비]": {
      "aliases": ["감가상각비"],
      "scope": "n13",              // 이 canonical_label은 주석13 표에서만 쓴다는 선언
      "_note": "주석13 판관비 명세 — 부분 금액. 주석4·12 전체 감가상각비와 다른 개념"
    },
    "감가상각비[전체]": {
      "aliases": ["감가상각비"],
      "scope": "n4,n12",
      "_note": "주석4·12 — 유형자산/원가성 전체 감가상각비"
    },
    "합계[주석20다]": {
      "aliases": ["합계"],
      "scope": "n20",
      "_note": "주석20다 전기초 배분표 — (1)+(2) vs (3) 검증 대상"
    }
  },

  "table_aliases": {
    // 사람이 읽는 이름 → table_id. fingerprint는 도구가 최초 실행 시 자동 채움
    // (헤더 행 텍스트 해시) — 이후 실행에서 달라지면 TABLE_SHIFT 경고.
    "주석9_퇴직급여손익표": { "table_id": "n9-t2", "fingerprint": "auto" },
    "주석9_배분표":         { "table_id": "n9-t3", "fingerprint": "auto" }
  },

  "assert_equal": [
    // canonical_label(+선택적 scope 한정) 단위로 "표가 달라도 값은 같아야 한다"를 선언.
    // 후보(같은 canonical_label/column_key/period_key/doc_key, 다른 table_id)가 실제로
    // 생겼을 때만 검증되고, 값이 다르면 finding으로 표면화된다.
    { "label": "이익잉여금" },
    { "label": "지분법손익" },
    { "label": "합계[주석20다]" }
  ],

  "exclude_pairs": [
    // canonical_label이 같은데(또는 같아 보이는데) 특정 표 쌍은 값이 달라도 정상 —
    // scope 분리로 못 끊는 잔여 케이스의 방어선(중복 등록 무방, 방어적).
    { "label": "감가상각비[판관비]", "table_alias_a": "주석13",
      "table_alias_b": "주석4·12 감가상각비", "reason": "부분 vs 전체" }
  ]
}
```

### 4-3. 검증 규칙 (로드 시 강제, 통과 못 하면 즉시 에러로 중단)

- `overrides`의 모든 canonical_label 키에 대해: alias 원문이 `GENERIC_TERMS =
  {"합계","계","소계","기초","기말","전기초","당기초","전기말","당기말", ...}`
  (core.TOTAL_LAB/tieout.SCE_END 등 기존 정규식과 겹치지 않게 별도 최소 집합으로 시작)에
  걸리면 **scope 필수**.
- `assert_equal`/`exclude_pairs`에 등장하는 label은 `overrides`나 `_common`에 실재해야 함.
- `table_aliases`의 `table_id` 형식이 2·3절 규약(`BS|IS|CI|CF|SCE` 또는 `n\d+-t\d+`)에
  맞아야 함.

## 5. 매칭 알고리즘

```
1. l2_extract로 튜플 전량 추출 (모든 표, 모든 셀 — **소액 컷 없음, 확정 2026-08-25**.
   MIN_WON(1억원) 재사용은 기각 — 정답셋 13건이 전부 1천원 차이라 컷을 걸면 전량
   걸러진다. L1의 컷은 표시 반올림 잡음 방지 목적이었고, L2는 금액 크기와 무관하게
   "같은 항목이 표마다 다르면 이상"이라는 성격이라 컷 자체가 성립하지 않는다.
   단, 단위 환산 1스텝 허용오차(refmap._pair_tol과 같은 원리)는 컷이 아니라 정확도
   보정이므로 그대로 유지한다. finding 정렬은 차이 절대액 내림차순.)
2. 각 튜플의 raw label을 canonical_label로 변환:
   - 회사 사전(overrides) → 실패 시 _common → 실패 시 UNMAPPED
   - scope가 있는 canonical_label 후보가 여럿이면(같은 alias, 다른 scope) table_id가
     scope 조건과 일치하는 것만 채택. 전부 불일치면 UNMAPPED(침묵 탈락 금지)
3. UNMAPPED은 전량 별도 섹션에 원문 라벨·건수·페이지와 함께 노출 (억지 매칭 금지)
4. 매칭된 튜플을 (canonical_label, column_key, period_key, doc_key) 키로 그룹화
5. 그룹 내 table_id가 2개 이상이고 value가 서로 다르면 후보(candidate)
6. 후보를 assert_equal/exclude_pairs와 대조:
   - assert_equal에 canonical_label(+scope 일치)이 있으면 → CONFIRMED(불일치 finding)
   - exclude_pairs의 table_alias 쌍과 일치하면 → EXCLUDED(억제, 별도 섹션에만 기록)
   - 둘 다 아니면 → UNDECLARED(finding으로 노출하되 등급 분리 — "assert_equal 등록
     필요 여부를 사람이 판단")
7. COL_SHIFT / TABLE_SHIFT / WEAK_COL 경고 별도 수집 (아래)
```

### 경고 3종

- **WEAK_COL**: 표에 헤더 텍스트가 없거나 period_key/column_key를 텍스트로 못 뽑아
  순수 위치(열 인덱스)로만 밀어붙인 경우. 해당 튜플에 플래그를 달아 finding에도
  "(WEAK_COL)" 태그로 동반 표시.
- **COL_SHIFT**: `column_key`가 위치 정보(`@c{n}`)를 포함하는데, 이전 실행(또는
  table_aliases 등록 시점)과 비교해 그 위치의 헤더 텍스트가 달라졌으면 발화.
  최초 실행분엔 비교 대상이 없으므로 미발화(정보 없음이지 이상 없음이 아님을 주석
  으로 명시).
- **TABLE_SHIFT**: `table_aliases`의 저장된 fingerprint와 이번 실행에서 그 table_id의
  실제 헤더 해시가 다르면 발화. `--update-fingerprints`로 갱신(gates.py 관행과 동일).

## 6. 산출물

### 콘솔 요약
```
L2 표간 대사 → 매칭 라벨 XX종 / UNMAPPED XX종(YY건)
  CONFIRMED  13건 (assert_equal 위반 — 검토 대상)
  UNDECLARED N건 (assert_equal도 exclude_pairs도 없음 — 등록 필요 여부 판단)
  EXCLUDED   N건 (exclude_pairs로 억제됨, 참고용)
경고: WEAK_COL Xp / COL_SHIFT Xp / TABLE_SHIFT Xp
```

### xlsx 시트 (`<원본>_L2대사.xlsx`, 별도 파일 — 기존 예외색인 xlsx와 분리)
```
CONFIRMED    canonical_label, period_key, column_key, table_id_a/b, value_a/b, 차이, 페이지
UNDECLARED   항목A, 항목B, 값A, 값B, 차이, 출처 페이지   (확정 2026-08-25, 사용자 지정 컬럼명)
EXCLUDED     〃 + reason
UNMAPPED     raw_label, table_id, page, 건수
WARNINGS     유형(WEAK_COL/COL_SHIFT/TABLE_SHIFT), table_id, 상세
```

정렬은 CONFIRMED/UNDECLARED 모두 차이 절대액 내림차순(2절 소액 컷 결정과 일관).

### `undeclared_suggestions.json` (확정 2026-08-25, xlsx와 별도 생성)

UNDECLARED 건마다 `assert_equal`/`exclude_pairs` 조각을 미리 만들어 둔다 — 회계사가
판단 후 고른 항목만 회사 사전(`labels/{회사}.json`)에 그대로 붙여넣도록.

```jsonc
{
  "schema": "dsd-l2-undeclared-suggestions/1",
  "generated_from": "<원본 pdf 파일명>",
  "suggestions": [
    { "kind": "assert_equal", "label": "...", "_evidence": {"table_id_a": "...",
      "table_id_b": "...", "value_a": ..., "value_b": ..., "page_a": ..., "page_b": ...} },
    { "kind": "exclude_pairs", "label": "...", "table_alias_a": "...",
      "table_alias_b": "...", "reason": "" }   // reason은 회계사가 채워 넣는 자리, 빈 문자열로 생성
  ]
}
```

`kind: "exclude_pairs"` 항목은 두 안을 모두 후보로 얹지 않는다 — 값이 다른 게
정상인지(exclude) 오류인지(assert_equal 위반으로 남겨야 함)는 회계사 판단 없이 도구가
추정하지 않으므로, 기본값은 `assert_equal` 후보만 생성하고 `exclude_pairs` 후보는
사람이 요청 시 별도 옵션(`--suggest-exclude`)으로만 추가한다.

**재실행 시 억제**: 이미 `assert_equal`/`exclude_pairs`에 등록된 (label[+scope],
table_id 쌍) 조합은 다음 실행에서 UNDECLARED에도 suggestions에도 다시 나타나지
않는다(확정 2026-08-25, "이미 선언된 조합은 빠진다").

   전면 구현하지 못했다 — `applies_to`는 그 임시 대체재(같은 안전성, 더 거친

   fingerprint 방식으로 정식 승격할 것.
3. **총계행 블록 분리(`table_id.b{n}`)** — 주석 표 하나(find_tables() 기준 1개)
