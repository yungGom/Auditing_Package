# 게이트 보고 — [핫픽스 B-6c] 주석 분할 단일 소스화 (2026-08-04)

## 1. 원인 추적 보고 (지시 1항)

**AI_Footing 조립은 B-6-mini 분할을 거친다 — 경로별 자체 분할(분기
지점)은 존재하지 않는다.** 전 산출 경로의 실제 흐름:

- UI 합계검증: `routers/workbench.py _run_foot` → `foot(세션 xlsx)` →
  `write_ai_footing(같은 xlsx)` — 세션 xlsx는 `extract` 산출물 하나뿐
- CLI 합계검증: `dsd_tool foot <xlsx>` — extract 산출물만 입력으로 받음
- 전기대사: `recon._to_xlsx` — 입력이 .dsd면 내부에서 `extract` 호출
- 시트 분할 자체는 전부 `extract → scanner.scan` 단일 소스

따라서 "경로 간 불일치"의 실체는 경로 분기가 아니라 **문서 형태 차이로
인한 extract(scanner) 자체의 실패**였다:

- 감사보고서 공시본은 주석 헤더가 USERMARK/SPAN 없이 평문인데, **주석
  2가 문단 중간 `…승인되었습니다.&cr;&cr;&cr;2. 재무제표 작성기준…`
  형태로만 존재** — P 시작 기준 평문 후보(1, 3, 4, …, 35)에 2가 빠짐
- 1차 체인 검증은 "1부터 +1 엄격 연속"이라 결번 2에서 체인 길이 1로
  붕괴 → note_mode "none" → 주석 전체(전 주석)가 마지막 FS 블록(CF)에
  흡수 — 재현 실측 CF 918행·주석 시트 0
- 동일 회사 반기 DSD는 헤더 1~24가 전부 P 시작 형태라 통과 — 같은
  경로, 다른 문서 형태

## 2. 수정 (scanner.py — 분할 로직만, repack·FS 불가침)

1. **주석 범위 산정 명확화(지시 3항)**: `'주석' TITLE ~ 다음 TITLE`
   (기존 SECTION-1 상한과 min 결합). 후반 '외부감사 실시내용'의 번호
   TITLE(1.~4.)·본문과 구조적으로 격리. TITLE이 없는 문서는 기존
   로직 그대로.
2. **&cr; 경계 폴백**: 1차 탐지가 "none"이고 주석 TITLE로 범위가
   확정된 경우에만, 문단 중간 `&cr;+N. 한글제목` 후보(`_NOTE_CR_RE`)를
   합집합하고 체인을 오름차순(건너뜀 허용)으로 완화해 재시도
   (note_mode "plain-cr"). 성공 문서의 기존 경로는 바이트 하나 안
   바뀜 — 반기 24개·삼성·조선내화 결과 불변.
3. 컨테이너(지시 4항)는 수정 불요 확인: `zipsplice`는 contents.xml만
   교체하고 다른 엔트리(내장 jpg 등)는 바이트 그대로 보존하는 설계 —
   픽스처로 실측 검증만 추가.
