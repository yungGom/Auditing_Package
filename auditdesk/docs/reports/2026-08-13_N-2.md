# 게이트 보고 — [N-2] DSD 탐색 수정 (2026-08-13)

## 원인 지점 보고 (지시 a — 진단 결론)

사용자 실측(폴더 경로 = "DSD 파일 없음" / 파일 경로 = 정상)의 원인
지점: **폴더 나열이 비거나 필터에서 떨어진 것이 아니라, 나열·필터
단계 자체가 부재**했다. 경로 입력은 작업 파일 생성의 파일 존재
검사(`isfile`)로 직행했고, 폴더는 파일이 아니므로 즉시 "DSD 파일이
없습니다"로 거부 — glob 특수문자·유니코드 정규화·경로 결합은 도달
전 단계라 무관(트레이스로 확인). 파일 열기·인코딩 정상 실측과 부합.

## 구현

- **`discover.resolve_dsd_path` 신설** (변환 로직 계층 — 라우터는
  얇은 래퍼): 파일 경로면 그대로, 폴더면 나열 후 확장자 필터.
  - 나열은 `listdir` 사용 — **glob 미사용**(대괄호 등 특수문자 함정
    원천 회피), 확장자 판정에 **유니코드 NFC 정규화**(OneDrive
    동기화 자모 분해 대비), **대소문자 무시**(.DSD 인정), 경로 결합은
    원본 이름 그대로 `os.path.join`.
  - 후보 1건 자동 채택 · `.dsd` 정확 1건이면 `.xml`보다 우선.
  - **0건·다건 = 파일별 제외 사유 보고** — "N개 항목 검토: xxx는
    확장자 불일치 · yyy는 폴더 · zzz는 편집기 프로젝트 파일(IXD)…"
    + **OneDrive 클라우드 전용 파일 안내** 병기 (침묵 실패 금지).
- **입력란 이중 수용 공식화**: 안내문 "또는 폴더 또는 파일 경로 직접
  입력 (폴더는 자동 탐색)". [파일 선택] 버튼(OS 대화상자)은 기존
  동선 유지 확인.
