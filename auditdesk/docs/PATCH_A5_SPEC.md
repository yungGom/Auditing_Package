# [패치 A-5] Footing 결과 엑셀 + 전기대사 — dsd_workbench 확장

> 확정사항: 전기대사 판정은 **TRUE/FALSE 2값** (법인 실무 표준 — 문용님 확인).
> 예시 파일: AI_Footing 산출물 10종 확보 (fixtures로 투입).
> 게이트 페어: 삼성전자 FY2024 DSD 확보 (기존 FY2025와 연속 2개년).

## A-5a. Footing 결과 엑셀 (AI_Footing 형식 재현)

### 타겟 형식 (예시 파일 실측 — AI_Footing_삼성전자 기준)
- **총괄표 시트**: 좌측 [시트정보: 시트|제목], 우측 [푸팅/크로스 에러: 시트|시트 링크|푸팅 오류|크로스 오류|총합]
  - 시트 링크 = 해당 시트로 하이퍼링크, 각 시트에는 "총괄표" 복귀 링크 (우상단)
  - 행 단위: BS/PL/PL 1/CE/CF + 주석 1..N (주석 제목 병기: "22. 판매비와관리비")
- **원문 시트**: 전체 통합 뷰 (기존 extract 산출 재사용)
- **개별 시트**: 기존 편집용 엑셀과 동일 배치 + 오류 셀 표시
- 용어 매핑: 푸팅 오류 = A-4 합계검증 (단수차+불일치), 크로스 오류 = 주석대사 미매칭

### 구현
1. CLI: `python -m dsd_tool foot 편집용.xlsx --excel` → `AI_Footing_{회사명}.xlsx` 독립 파일
2. A-4의 _FOOT 검증 결과를 총괄표 카운트로 집계, 오류 셀은 개별 시트에 하이라이트
   (예시 파일의 표시 방식 정밀 확인 필요 — 구현 시 예시 10종에서 오류 셀 서식을
   실측해 동일하게: 채우기/폰트색/테두리 중 무엇인지. read_only 아닌 모드로 스캔)
3. 예시 10종을 `fixtures/ai_footing/`에 배치 — 형식 게이트의 기준

### 게이트 A-5a
1. 삼성전자 FY2025로 생성 → 예시 AI_Footing_삼성전자와 **시트 구성·총괄표 열 구조 동일**
2. 총괄표 오류 카운트가 A-4 _FOOT 결과와 정합 (예시 파일 카운트와의 차이는
   알고리즘 차이일 수 있으므로 불일치 시 건별 원인 분류 리포트 — 우리가 더 정확할 수 있음)
3. 하이퍼링크 왕복(총괄표↔시트) 동작

## A-5b. 전기대사 (당기 보고서의 전기값 ↔ 전기 보고서의 당기값)

### 판정 규칙 (확정)
- 판정 열: **TRUE / FALSE 2값만** (법인 표준)
- FALSE의 사유는 비고 열에: `값 상이 (차이 ±N)` / `전기 보고서에 항목 없음`
- 요약 시트 상단에 안내 1줄: "FALSE 존재 시 전기 재작성·계정 재분류 여부를 확인하십시오"
  (판정은 기계, 해석은 회계사)

### 입력 모드 3종
```
① 계속감사: 당기 DSD + 전기 DSD (로컬 파일 — 이번 게이트 대상)
② 초도감사: 당기 DSD + OpenDART 수신 전기 공시
   ②-1 공시원본(document.xml)이 DSD 호환 형식이면 → dsd_tool extract 재사용 (전체 대사)
        ※ B-2에서 확보한 원본 수신물로 호환성 사전 확인 — 호환이면 이 경로가 기본
   ②-2 비호환 시 폴백: XBRL 팩트(fnlttSinglAcntAll 또는 B-3 인스턴스) 대사 — 본문 한정,
        주석은 "수동 확인 필요" 목록으로 출력 (허위 자동화 금지)
③ 파일 직접 지정: --prior <전기.dsd 또는 전기_편집용.xlsx>
```
- CLI: `python -m dsd_tool recon 당기.dsd --prior 전기.dsd`
       `python -m dsd_tool recon 당기.dsd --prior-opendart "회사명" --year 2024`
- 모드 ②는 dart_explorer 기능 호출이므로 **dsd_workbench에서 직접 네트워크 금지 원칙 유지**:
  recon은 "dart_explorer가 미리 받아둔 캐시 파일 경로"를 입력받는 형태로 경계 보존
  (원클릭은 dart_explorer 측 명령이 수신 후 workbench recon을 호출하는 방향)

### 대사 로직
1. **본문 (BS/PL/CE/CF)**: 당기 파일의 "전기 열" ↔ 전기 파일의 "당기 열"
   - 계정 매칭: A-4의 계정명 정규화(공백·로마숫자·번호 제거) 재사용
   - CE는 행(변동내역)×열(자본항목) 2차원 매칭
2. **주석**: 주석 매칭은 번호가 아니라 **제목 정규화**로 (연도 간 번호 이동 대응)
   - 표 내부: 행·열 라벨 매칭 후 "전기(말) 열" ↔ 전기 보고서의 "당기(말) 열" 셀 대조
   - 서술문 내 숫자는 스코프 제외 (표만 — 서술문 대사는 오탐 과다)
3. 값 비교: 절대값 ±0 엄격 일치 = TRUE (전기대사는 단수차 허용 없음이 원칙,
   --tolerance 옵션으로만 완화 가능)

### 출력: `전기대사_{회사명}.xlsx`
- [요약]: 전체 판정 TRUE/FALSE, 본문/주석별 (대사 N · TRUE n · FALSE m), 안내문
- [본문 시트들]: 계정과목 | 당기보고서 전기값 | 전기보고서 당기값 | 판정 | 비고
- [주석 시트들]: 주석 제목 매핑표 + 표별 셀 대조 상세
- A-5a 총괄표 형식과 톤 통일 (하이퍼링크·시트 구성 관례 동일)

### 게이트 A-5b
1. **삼성전자 FY2025 ↔ FY2024 (실파일 페어)**: 본문 전기열 전수 대사 —
   기대: 대부분 TRUE (삼성전자는 재작성 없었을 것). FALSE 발생 시 건별 검토 리포트
2. 주석 제목 매칭률 + 표 대사 실행 (최초 실행이 벤치마크 — 결과 보고 후 기준 확정)
3. 변조 테스트: FY2024 사본의 당기값 1개 +1 → 해당 셀만 FALSE
4. 모드 ② 사전 확인: B-2 수신 공시원본 1건의 DSD 호환성 판정 리포트
   (호환 여부에 따라 ②-1/②-2 분기 확정 — 결과를 기획 세션에 회신)
