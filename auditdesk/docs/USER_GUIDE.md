# AuditDesk 사용설명서 (USER_GUIDE)

> 대상: 감사팀 회계사 (XBRL·DSD 실무 담당).
> 구성: 실제 업무 시나리오 5개 — 각각 진입점 → 클릭 순서 → 산출물 읽는 법 →
> 확인 포인트 순서로 따라가면 된다. 기능 사전이 아니라 업무 동선 안내서다.
> 부록: '원칙'(도구가 왜 이렇게 동작하는가) / '한계'(안 되는 것과 그 이유).
>
> 실행: `RUN.bat` (또는 `python -m auditdesk --port 8710`) →
> 브라우저 `http://localhost:8710`. **완전 로컬 실행 — 고객사 데이터는 밖으로
> 나가지 않는다** (우상단 "로컬 전용 — 외부 전송 없음" 뱃지가 그 표시다).
> 필요한 유일한 외부 통신은 OpenDART **수신**뿐이며(공개 공시 다운로드),
> API 키는 설정 화면에서 감지 상태만 확인한다 (.env 파일에만 보관).

## 시나리오 ① 동종업계 주석 양식 참고 — "다른 회사는 이 주석을 어떻게 태깅했나"

신규 주석을 작성하거나 태깅 방식이 애매할 때, 같은 업종 회사의 실제 공시
XBRL을 차원표 엑셀로 받아 편집기 입력값(레이블·ID)까지 그대로 참고한다.

**진입**: 좌측 사이드바 DART EXPLORER → **공시 검색**

**클릭 순서**
1. 회사명 입력(자동완성) 또는 **업종 필터**에 업종코드 입력.
   최근 작업한 회사와 같은 업종을 훑으려면 **[동종업계 보기] 토글** —
   최근 세션 회사의 업종이 자동 프리셋된다 (회사 미지정 시 최근 공시
   3페이지까지 스캔).
2. 결과 행에서 **[차원표 엑셀]** 클릭. 이 2클릭이 전부다 —
   XBRL 수신 → 렌더 → 엑셀 다운로드까지 자동.

[SCREENSHOT: 공시 검색 화면 — 업종 필터·동종업계 토글과 결과 행 4버튼]

**산출물 읽는 법** (BS/PL/CF/CE + 주석 번호별 시트, 신원 기준 34개)
- 각 행 우측 3열이 **편집기 입력 열**: **[한글 표준레이블]** — 금감원 편집기
  검색창에 그대로 넣는 검색어 / **[영문명]** — element name /
  **[ID]** — QName(`prefix:name`).
- **"확장"** 표시 = 그 회사가 만든 회사 고유 확장요소라는 뜻.
  **내 공시에 그대로 가져다 쓸 수 없다** — 표준 대체 후보를 찾거나
  우리 회사 확장을 새로 정의해야 하는 항목이라는 신호다.
- 시트 상단에 표준/확장 **충전율**이 표기되고, 표의 열 축 구성은
  상단 '[열 요소]' 소표에 정리되어 있다.

**확인 포인트**: 참고하려는 행이 "확장"인지 먼저 본다. 표준이면 레이블
그대로 편집기 검색, 확장이면 양식(계층 위치·차원 구성)만 참고.

## 시나리오 ② 공시 엑셀 열람 — "이 회사 감사보고서를 엑셀로 보고 싶다"

**진입**: DART EXPLORER → **공시 검색**

**클릭 순서**: 검색 → 결과 행 **[엑셀로 변환]**. 역시 2클릭 —
공시 원본(document.xml) 수신 → DSD 형식 래핑 → 추출까지 자동으로
엑셀이 열린다 (신원 기준 5,554셀).

**산출물 읽는 법**
- 시트 구성은 편집기 DSD 추출과 동일 (본문 FS + 주석 시트).
- 마지막 **'원문' 통합 시트**: 전 시트를 `[[시트명]]` 구분자로 세로로
  이어 붙인 것 — 전체 검색(Ctrl+F)용. 참조 전용이며 이 시트를 고쳐도
  역변환에 반영되지 않는다 (`_MAP` 미포함 — 구조적으로 안전).

**확인 포인트 (중요)**: OpenDART로 받은 원본은 **열람·분석용**이다.
주석 분할이 부정확할 수 있어(실측: 신원 주석이 3개 덩어리로만 감지)
**편집·repack 왕복은 반드시 편집기(dartdb)에서 나온 DSD 기준**으로 한다.
필요하면 결과 행 [DSD 저장]으로 원본을 보관할 수 있다 (읽기 전용 수신물).

## 시나리오 ③ 분반기 첫 공시 작성 — "기말은 해봤는데 반기 XBRL은 처음"

자기 회사의 **기말 인스턴스가 있으면** 태깅을 새로 고민할 필요가 없다.
기말에 확정했던 element·확장·role을 그대로 승계하고, 기간만 분반기로
변환하며, 진짜 새로 생긴 계정만 추천을 받는다.

**진입**: 두 가지 —
- 공시 검색에서 자기 회사 검색 → 결과 행 **[워크시트]** (DSD 수신 후
  경로가 프리셋된 채 Studio로 이동), 또는
- 사이드바 XBRL STUDIO → **작성 워크시트**에서 직접 DSD 선택.

**클릭 순서**
1. 모드에서 **승계(inherit) × 반기(half)** 선택.
2. 기준이 될 **자기 기말 XBRL 패키지** 선택 — '최근 수신 패키지'
   드롭다운에서 고른다 (경로 복사 불필요).
3. 실행 → 워크시트 엑셀 산출.

[SCREENSHOT: 작성 워크시트 화면 — 모드 선택과 최근 수신 패키지 드롭다운]

**산출물 읽는 법** (삼성 실측: 본문 118행 = 승계 107 · 신규 11 · 폐지 0)
- **승계 행**: '승계 — 기말 사용(팩트 N)' 근거가 붙는다. 기말에 실제로
  쓴 element라는 뜻 — 그대로 채택하면 연도 간 일관성이 유지된다.
- **신규 행**: 기말에 없던 계정만 D-3b 추천(Top-4)이 붙는다.
- **폐지 표시**: 승계하려는 element가 신버전 택소노미에서 폐지된 경우
  대체 후보가 첨부된다 (D-4c).
- 기간 문맥(당기/전기 × 누적/3개월 + 시점)은 자동 변환되어 있다.
- 주석 범위는 기말과 거의 유사하다는 전제 — role·제목은 결정적으로 승계.

**전사 순서 (도구 밖 작업)**
1. 워크시트의 **확정☐**를 행마다 회계사가 직접 기입한다 —
   ☐가 비어 있으면 그 워크시트는 "완성 아님"이다.
2. 금감원 편집기에서 '편집기 검색어'(=한글 표준레이블)로 element를
   찾아 전사한다. **도구는 편집기에 업로드하지 못한다** — 산출물은
   전사 가이드까지이고, 인스턴스 생성은 편집기가 유일한 경로다.

**확인 포인트**: 승계 정확도는 실측 100%(오승계 0)지만, "신규"로 뜬
행 중 일부는 회사가 연도 간 element 선택을 바꾼 동개념 이형일 수 있다
— 기말 유사 승계 제안이 붙어 있으면 일관성 관점에서 검토.

## 시나리오 ④ 완전 신규 공시 작성 — "XBRL 첫 제출, 참고할 자기 인스턴스가 없다"

**진입**: 시나리오 ③과 동일하되 모드를 **신규(new)** 로 선택.

**F-1 본문 워크시트 읽는 법**
- 계정과목별 **추천 element Top-4** — 3,976개 상장사 코퍼스에서 같은
  계정명이 실제로 어떤 element로 태깅됐는지의 실증 순위다 (동업종 ×2
  가중, LLM 불사용). 1순위가 기본 배치되고 대안이 병기된다.
- **확신도**: 코퍼스 근거의 강도. 낮으면 대안까지 열어 보라는 신호.
- **확장 필요**: 코퍼스 정답이 확장요소인 구간 — 표준으로 못 덮는
  계정이니 회사 확장 정의를 검토하라는 뜻.
- **매핑 확정** 화면(Studio)에서 추천 카드를 확정하면 기록이 남고
  (누가·언제), 이후 V-1 대사(시나리오 ⑤)가 이 확정을 최우선으로 쓴다.
- RecCard 상태 4종: 추천(recommend) / 확정(confirmed, 잠금) /
  확장(extension) / 표준(standard) — 근거 뱃지(실증·유사도·동업종)와
  함께 표시.

**F-2 주석 워크시트 읽는 법**
- 주석마다 **role 배정**(D2·D3… 어느 공시 섹션인가) + 표 행의
  **3분류 라우팅**: a 항목(계정 행) / b member(차원 멤버 행) /
  c 수동(판단 필요) — 침묵 누락 없이 전 행이 셋 중 하나로 나온다.
- 표에 축이 배정되지 못하면 행에 '⚠ 표 구조 미확정 — member 가능성
  확인'이 병기된다. 숨기지 않고 노출하는 것이 원칙이다.
- 서술문은 텍스트블록으로 분류된다.

**확인 포인트**: 추천은 추천일 뿐이다. 동명이의(현금및현금성자산이
계정인지 member인지 등) 구간은 도구가 판단하지 않는다 — 확정☐가
회계사의 서명이다.

## 시나리오 ⑤ 제출 전 검증 3종 — Footing → 전기대사 → XBRL 대사

제출 직전, 세션의 **Footing 탭** 서브탭 3개를 왼쪽부터 차례로 통과시킨다.

**진입**: DSD WORKBENCH → **세션** → 대상 세션 열기 → **Footing** 탭

**1단계 — 합계검증·주석대사 (A-5a)**
- 화면에서 일치/단수차/불일치/주석 미매칭 집계 확인.
- 합계 레벨이 잘못 잡힌 행은 화면에서 **레벨 오버라이드**(수동 지정)
  후 재검증 — 기존 `_FOOT` [레벨] '수동' 열 관례의 자동화다.
- AI_Footing 형식 엑셀(법인 산출물 양식)로 내보내기: 총괄표
  (푸팅/크로스 에러 집계, 하이퍼링크로 오류 셀 왕복) + 오류 셀
  노랑 하이라이트/메모.

**2단계 — 전기대사 (A-5b)**
- 당기 보고서의 전기값 ↔ 전기 보고서의 당기값 대조. 판정은
  TRUE/FALSE 2값 + 비고, 허용오차 ±0 엄격(완화는 오차 입력만).
- 전기 소스 3모드: 계속감사(로컬 페어) / 초도(OpenDART 수신 —
  화면의 소스 뱃지로 로컬/캐시 구분) / 직접 지정.
- FALSE가 나오면: [FALSE분해] 시트에서 원인 분류부터 본다 —
  '항목없음'은 신규 공시행, '제목 미매칭'은 신규 주석일 수 있다
  (주석은 제목 정규화 매칭이라 번호 이동에는 강하다).

**3단계 — XBRL 대사 (V-1)** — 태깅이 공시 본문과 일치하는가 (최종 관문)
1. 서브탭 **XBRL 대사 (V-1)** → '최근 수신 패키지'에서 자기 회사
   인스턴스 선택 → **[XBRL 대사 실행]**.
2. 배너: **대조율**(매칭/전체)과 5분류 칩 — 일치 / 값 상이 /
   태깅 누락 / 인스턴스에만 / 매핑 없음. 허용오차 사용값(자동:
   decimals·표시단위 기반, 또는 수동 오버라이드)도 여기 표기된다.
3. 기본 필터는 **FALSE만** — 여기 남는 행이 할 일 목록이다.

[SCREENSHOT: XBRL 대사 서브탭 — 대조율 배너·5분류 칩·FALSE 필터 테이블]

**FALSE·매핑 없음이 떴을 때 회계사가 할 일**
- **값 상이**: 태깅 값·단위(천원/백만원)·문맥(연결/별도)을 확인.
  유동/비유동 구분 차이 같은 실제 태깅-본문 불일치가 여기서 드러난다
  — 이 도구의 존재 이유다. 편집기에서 수정 후 재실행.
- **태깅 누락**: 매핑은 있는데 인스턴스에 당기 팩트가 없음 —
  편집기에서 해당 element 태깅 여부 확인.
- **매핑 없음**: 오류가 아니라 **판정 불가** — F-1 확정 기록도 F-3
  승계도 없는 계정이다. Studio '매핑 확정'에서 확정을 쌓으면
  다음 실행부터 대조율이 올라간다 (도구는 임의로 추측 매칭하지 않는다).
- **인스턴스에만**: 인스턴스에는 있는데 DSD 본문 행에 대응이 없는
  element — 엑셀의 별도 시트에서 무차원/차원(멤버 조합) 구분으로 확인.
- 엑셀 다운로드: 요약(대조율·판정 분포·허용오차) + 시트별 상세
  (FALSE 빨강, 매핑 없음 노랑, 한글 표준레이블 열 포함).
- 입력 DSD가 OpenDART 래핑 수신물이면 노란 경고 배너가 뜬다 —
  본문 대사는 유효하지만 참고용이며, 제출 검증은 편집기 DSD로.

**확인 포인트**: 판정은 기계, 해석은 회계사. FALSE 0이 목표가 아니라
**FALSE의 사유를 전부 설명할 수 있는 상태**가 목표다.

## 부록 A. 원칙 — 도구가 왜 이렇게 동작하는가

| 원칙 | 실무에서의 의미 |
|---|---|
| DSD 창작 불가 — 뼈대 + 값 교체만 | 도구는 기존 DSD의 값을 위치 기반으로 바꿀 뿐, XML 구조를 만들지 않는다. 초도감사는 유사회사 DSD, 계속감사는 전기 DSD가 뼈대다. dart4.xsd 검증을 통과하는 유일한 안전 경로. |
| 위치 기반 교체 | 셀↔XML 오프셋을 `_MAP`에 기록해 두고 그 자리만 바꾼다. 같은 값이 여러 곳에 있어도 오교체가 없다 ("바뀌다 말고" 문제의 원천 해결). `_MAP` 시트는 건드리지 말 것. |
| 버전 정보는 공식 도구가 | meta.xml의 editver/docver를 도구가 수정·창작하지 않는다. 버전 변환은 DART 편집기 고유 기능. |
| 자동은 추천, 확정은 회계사 | 모든 매핑·role·축 배정은 제안이다. 확정☐ 기입 전에는 "완성 아님". LLM API를 쓰지 않으며 근거는 코퍼스 실증+규칙 — 그래서 추천마다 근거가 표기된다. |
| 수신 허용·송신 금지 | OpenDART 다운로드만 한다. 고객사 데이터의 업로드·웹훅·텔레메트리는 코드 자체가 없다. 편집기 업로드도 불가 — 산출물은 전사 가이드. |
| 두 앱 경계 | 수신=dart_explorer, 변환·대사=dsd_workbench. 연결은 캐시 폴더의 파일뿐. dsd_workbench에는 네트워크 코드가 일절 없다. |
| 미매칭 ≠ 0 | 매핑 없음·미매칭·라우팅 실패는 숨기지 않고 그대로 노출한다. 숫자가 예뻐 보이는 것보다 판정 불가를 정직하게 보여주는 게 감사 도구의 의무. |
| 요약=상세 단일 소스 | 요약 수치는 상세의 재집계다 — 요약과 상세가 다를 수 없는 구조. |
| 게이트 후 커밋 | 모든 패치는 실데이터 게이트 통과 후 커밋되며 GATES.json(29)이 단일 기록이다. |
