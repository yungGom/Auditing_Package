## D-1. 택사노미 트리 뷰 (이미지2 형식) — 기반 작업, 난이도 하

**입력**: XBRL 패키지 폴더 (인스턴스 + pre.xml + lab-ko.xml + lab-en.xml + xsd)
**출력**: 엑셀 — Role별 시트, 열 구성 이미지2 그대로:
`표시 한글명(들여쓰기 트리) | Prefix | 표시 영어명 | ID | 기본 한글명 | 기본 영어명`

**구현**:
1. pre.xml의 presentationLink(Role별) → parentChildArc(order 정렬)로 트리 재구성
2. lab-ko/lab-en에서 라벨 결합 (preferredLabel role 반영: terseLabel/periodStartLabel 등)
3. xsd의 회사 확장 element(prefix가 entity/회사코드인 것) → **빨간 글씨** 표시 (이미지2의 자본위험[구성요소]처럼)
4. 들여쓰기 = 트리 depth, [축]/[구성요소]/[합계] 접미사는 라벨 그대로 보존
5. 금감원 택사노미 xlsm(Presentation Link 71,276행)도 같은 뷰어로 열람 가능하게
   (표준 트리 vs 회사 인스턴스 트리를 같은 형식으로 — 비교의 기초)

**게이트 D-1**: entity00136925 패키지 → Role 5개 트리 정확 재구성 (pre.xml 아크 133개 전수 반영),
확장 element 0개 파일이므로 삼성전자 XBRL(B-3 캐시)로 확장 element 표시 확인

## D-2. 차원 표 렌더러 (이미지1 형식) — 핵심 난제, 난이도 상

DART 뷰어가 D822380 같은 주석을 표로 그리는 것과 동일한 작업.

**입력**: XBRL 패키지 + Role 선택 (예: D822380)
**출력**: 엑셀 — 이미지1 레이아웃:
- 열: 축(axis)의 구성요소(member) 조합 — **중첩 헤더** (축이 2개면 2단 헤더)
- 마지막 열: [합계] = 차원 미지정(default member) 팩트
- 행: LineItems (pre.xml order 순)
- 셀: (element, 기간, 축=member 조합)이 일치하는 팩트 값
- 음수는 빨간 괄호 `(212,324,000)`, 기간별 블록 분리 "(기간: 당기)/(전기)"

**구현 순서 (난이도 단계별 게이트)**:
1. **축 0개** (재무제표 본문): 행=element, 열=기간 → 사실상 xbrl_extract 재배열. 게이트: BS 본문 표 재현
2. **축 1개** (예: 자본변동표 ComponentsOfEquityAxis): 열=구성요소+합계. 게이트: 올려준 인스턴스의 자본변동표(축 컨텍스트 16개)를 DART 뷰어와 동일 배치로 재현
3. **축 2개 중첩** (이미지1: 금융상품종류 × 장부금액/손상차손누계): 데카르트 조합 헤더.
   게이트: 삼성전자급 대형 인스턴스에서 이미지1 형식 재현, DART 뷰어 화면과 육안 대조
4. def.xml 파싱: definitionArc의 all(LineItems→Table)·hypercube-dimension·
   dimension-domain·domain-member 아크롤 체인으로 표 구조 결정
   (주의: 파일에 따라 dimension-member 대신 domain-member 사용 — 아크롤명 유연 처리)

**스코프 제외**: typed dimension (DART 재무공시에선 드묾 — 발견 시 후속), 웹 렌더링(Phase C에서)

## D-3. 계정과목 → element 매핑 추천 (전업종 코퍼스) — 난이도 중

**[D-3a] 코퍼스 구축** (dart_explorer, 주기 실행):
1. B-1 검색으로 전업종 XBRL 제출사 목록 (상장사 전체 — corp_code 파일 기반)
2. B-3 파이프라인으로 XBRL 일괄 다운로드 (캐시 영구, 일 한도 2만건 내 배치 — 약 2,500사 기준 수일)
3. 각 인스턴스에서 추출: (element ID, 회사 라벨(lab-ko), 표준 라벨, 업종코드, Role,
   차원 문맥, 사용 회사수) → `mapping_corpus.sqlite`
4. 확장 element는 별도 테이블 (표준에 없는 계정을 회사들이 어떻게 정의했는지 — 신규 계정과목의 최고 참고자료)

**[D-3b] 매핑 조회** (dsd_workbench 성격 — 완전 로컬, 고객사 계정명이 외부로 안 나감):
1. 입력 템플릿 (고정 3열): `계정과목명 | 구분(BS/PL/CE/CF/주석) | 비고`
2. 후보 스코어 = 가중합:
   - 실증 빈도: 코퍼스에서 유사 라벨로 해당 element를 쓴 회사 수 (동업종 가중치 ×2)
   - 문자열 유사도: 자모 분해 편집거리 + 토큰 자카드 (한글 계정명 특화)
   - Role 정합: 구분(BS)과 element 소속 Role(D210000계열) 일치 여부
3. 출력 엑셀: 계정과목명당 후보 **Top 4**, 각 후보에
   `element ID | 표준 한글라벨 | 근거("동업종 12사 사용" 등) | 기준서 Reference(xlsm Reference Link) | 선택☐`
4. 자동 확정 없음 — 선택 열은 회계사가 기입 (원칙 유지)

**게이트 D-3**: 코퍼스 100사 파일럿 구축 → 기존 클라이언트 계정과목 20개로 블라인드 테스트,
Top 4 안에 정답 포함률 측정 (목표 80%+, 미달 시 스코어 가중치 조정)
