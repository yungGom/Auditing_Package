# [패치 D-4 / A-3+] 업데이트 관리 스펙 — 택사노미 버전 & DART 편집기 버전

> 배경: 택사노미는 매년 개정(폐지/신설/라벨변경), DART 편집기도 수시 업데이트.
> 원칙: 버전 변환은 공식 도구(금감원 택사노미 배포, DART 편집기)가 하고,
>        우리 도구는 감지 → 대조 → 리포트 → 재검증만 담당한다. 버전 정보를 창작하지 않는다.

---

## Part 1. [패치 D-4] 택사노미 버전 관리 (XBRL)

### D-4a. 버전 저장소
- `dart_explorer/taxonomies/{버전}/` 에 연도별 택사노미 적재
  (소스: 금감원 배포 xlsm 또는 공식 패키지 — 사용자가 수동 다운로드 후 투입)
- `corpus load-standard`에 `--version` 태그 추가 → standard_labels에 version 열
- 코퍼스 usages에도 대상 사업연도(이미 있음) 기준으로 어느 택사노미 세대인지 식별 가능하게

### D-4b. 버전 diff 리포트
- CLI: `python -m dart_explorer taxdiff <구버전> <신버전>`
- 출력 엑셀 3시트:
  1. 신설 element (신버전에만 존재) — ID, 라벨, 소속 Role
  2. 폐지 element (구버전에만 존재) — deprecated 마킹 포함
  3. 변경 element (ID 동일, 라벨/Role/참조 변경)
- 구현: 두 버전의 Presentation Link + Concepts 대조 (D-1 파서 재사용)

### D-4c. 인스턴스 호환성 점검 (프로세스 지도 C4의 구현)
- CLI: `python -m dart_explorer taxcheck <전기 XBRL 패키지> --against <신버전>`
- 전기 인스턴스에서 사용한 element 전수 ↔ 신버전 택사노미 대조:
  1. 그대로 사용 가능 (녹색)
  2. **폐지됨** → D-3b 매핑 엔진으로 대체 후보 Top 4 자동 제시 (노랑)
  3. 라벨/Role 변경 → 변경 내용 표시 (파랑)
- 결승 산출물: "당기 XBRL 착수 전 체크리스트" 엑셀 — 시즌 시작 시 클라이언트별 1회 실행

### D-4d. 확장→표준 승격 감지
- 대상: 코퍼스 extensions 테이블의 확장 element (7,906건 축적됨) + 자사 작성 확장
- 신버전 diff의 "신설 element" 목록과 라벨 매칭 (D-3b 스코어러 재사용: 자모편집거리+토큰자카드)
- 출력: "작년 확장 X ≈ 올해 신설 표준 Y (유사도 점수)" 추천 리스트 — 확정은 회계사
- D-4c 리포트에 통합 (전기에 확장을 썼던 항목은 승격 후보 자동 첨부)

### 게이트 D-4
- 실제 두 세대 택사노미(예: 2025 vs 2026 xlsm) 확보 시 diff 실행 → 신설/폐지 건수 리포트
- 홀드아웃 회사 1곳의 전기 인스턴스로 taxcheck → 폐지 검출 + 대체 후보 제시 확인
- 두 세대 xlsm 확보 전이라도: 합성 diff(현행 xlsm에서 일부 element 제거/개명한 사본)로 로직 게이트 먼저

## Part 2. [A-3 확장] DART 편집기 버전 대응 절차 (DSD)

### 방침 (불변)
1. **우리 도구는 meta.xml의 editver/docver를 절대 수정·창작하지 않는다**
   (근거: 밑바닥 생성 DSD의 스키마 검증 실패 사례 / 버전 변환은 편집기 고유 기능)
2. repack 산출물은 항상 뼈대 DSD의 버전을 그대로 상속한다
3. 위치 기반 extract는 직렬화 형식(줄바꿈·속성순서)에 무관하므로,
   새 버전이 형식을 바꿔도 재스캔으로 흡수된다 — 단 G2로 반드시 확인

### 새 편집기 버전 출시 시 절차 (KNOWN_VERSIONS.md에 이 절차 명문화)
```
1. 대표 DSD 1개(예: 한빛정밀 클린본)를 새 편집기에서 열기 → 저장
   → 편집기가 새 버전으로 변환한 파일 확보 (예: *_6_1변환.dsd)
2. 변환본을 fixtures/real/에 세대 추가
3. batch_validate 실행: 변환본 extract → 무변경 repack → G2(내용 동일) 확인
4. 통과 → KNOWN_VERSIONS.md에 신버전 행 추가 (editver, 확인일, G2 결과)
   실패 → 직렬화 차이 리포트를 기획 세션으로 회신 (진행 중단)
5. 이후 신버전 뼈대 사용 가능. 구버전 DSD는 계속 열림(편집기 하위호환)
```

### [소패치 A-3b] version-check 명령
- CLI: `python -m dsd_tool version-check <파일.dsd>`
- 동작: editver 추출 → KNOWN_VERSIONS.md 대조 → 미확인 버전이면
  위 절차 안내 출력 + 즉석 G2 스모크(무변경 왕복 내용동일) 실행 결과 표시
- E-0 대시보드에 "확인된 편집기 버전" 카드 추가 (KNOWN_VERSIONS.md 렌더)

### 게이트
- 기존 세대(5.106/5.107/6.0변환) 3종에서 version-check 정상 판정
- 가짜 editver 픽스처로 미확인 경고 + 안내 절차 출력 확인
