## 1. [패치 D-2b] 차원 표 렌더러 보완 — 육안 검증 피드백 2건

D-2 육안 대조 결과: **숫자 배치는 정확** (검증 완료). 아래 2건은 표시 개선.

### 1-1. 기간 블록 라벨 수정 (반기·분기 보고서)
- 현상: 기간 블록이 "반기/전기/전전기/4기전"으로 표기됨
- 실제 의미: 반기보고서의 duration 컨텍스트 4종은
  **당기 3개월 / 당기 누적 / 전기 3개월 / 전기 누적**
- 수정 규칙 (컨텍스트 기간으로 판정, 라벨 추측 금지):
  - duration의 (시작일, 종료일)에서: 종료일이 보고기준일과 같은 해 → 당기, 전년 → 전기
  - 기간 길이 ≈ 3개월 → "3개월", 기간이 회계연도 개시일부터 → "누적"
  - 표기: `당기 3개월 (2025-04-01 ~ 2025-06-30)` 처럼 실제 일자 병기
  - instant 컨텍스트: 당기말 / 전기말 / 전기초 (기준일 병기)
  - 사업보고서(연간)는 기존처럼 당기/전기 (3개월 블록 없음)
- 분기보고서(3분기 누적 9개월 등)도 같은 규칙으로 일반화될 것

### 1-2. 시트명을 사람이 읽을 수 있게
- 현상: 시트명이 택사노미 role 코드 (D210000 등)
- 변경: **DSD 편집용 엑셀과 동일한 명명 체계** — BS / PL / PL1 / CE / CF / 1, 2, 3, ...
  - 재무제표 role → 약칭 매핑: 재무상태표 계열(D210000/D220000)→BS,
    손익계산서 계열(D310000/D320000)→PL, 포괄손익 별도 role 존재 시→PL1,
    자본변동표(D610000)→CE, 현금흐름표(D510000/D520000)→CF
    (role 정의 텍스트로 판정 — 코드 하드코딩 대신 "재무상태표" 등 명칭 매칭 우선)
  - 주석 role (D8xxxxx) → role 코드 오름차순으로 1, 2, 3, ... 순번
  - 연결·별도가 모두 렌더되는 경우: 연결이 기본, 별도는 `BS_별도` 접미사
  - **추적성 보존**: 각 시트 1행에 원래 role 코드와 정의 전문 기재
    (예: `[D822100] 주석 - 유형자산 - 연결`) — 코드가 사라지면 안 됨
- 시트명 31자 제한·중복 충돌 처리 포함

### 게이트 D-2b
1. 신원(반기) 재렌더 → 기간 블록이 "당기 3개월/당기 누적/전기 3개월/전기 누적" + 일자 병기
2. 삼성전자(연간) 재렌더 → 시트명 BS/PL/.../1,2,3..., 각 시트 1행에 role 코드 보존
3. 기존 D-2 자동 테스트 무회귀
4. 산출물 2종 재생성 → 사용자 육안 재확인 (바탕화면 XBRL 폴더)

## 2. [패치 D-4] 택사노미 버전 관리 (XBRL)

> 배경: 택사노미는 매년 개정(폐지/신설/라벨변경).
> 원칙: 버전 변환·배포는 금감원이 하고, 우리 도구는 감지 → 대조 → 리포트만 담당.

### D-4a. 버전 저장소
- `dart_explorer/taxonomies/{버전}/` 에 세대별 택사노미 적재
- **실파일 2세대 확보 완료** (사용자 제공 — 아래 경로에 배치할 것):
  - `taxonomies/2024-06-30/` ← 금융감독원_DART_XBRL_Taxonomy_Search_배포용_20251513_.xlsm
  - `taxonomies/2026-01-31/` ← 1__DART_Taxonomy_20260630_배포용.xlsx
  - 버전명은 파일 내 참조 pre.xml 기준일 (dart_all_YYYY-MM-DD_pre.xml)
- `corpus load-standard`에 `--version` 태그 추가 → standard_labels에 version 열
- 코퍼스 usages도 사업연도 기준으로 택사노미 세대 식별 가능하게

### D-4b. 버전 diff 리포트
- CLI: `python -m dart_explorer taxdiff <구버전> <신버전>`
- 출력 엑셀 3시트:
  1. 신설 element (신버전에만) — ID, 한글라벨, 소속 Role
  2. 폐지 element (구버전에만) — deprecated 마킹
  3. 변경 element (ID 동일, 라벨/Role/참조 변경)
- 구현: 두 버전의 Presentation Link + Concepts 대조 (D-1 파서 재사용)
- **[보충 — 실파일 실측 반영]**:
  - **열 배치가 세대별로 다름** — 헤더 행에서 열 역할 탐지, 열 위치 하드코딩 금지
    (2026판: prefix|role정의|element|한글라벨 순 / 2025판은 상이)
  - **게이트 기대값 (claude.ai 사전 실측)**: 신설 **1,334** / 폐지 **156** / 유지 **7,652**
    (±소량 오차 허용 — 파싱 방식 차이. 크게 다르면 진행 중단 후 원인 보고)
  - 라벨 변경 검출은 양쪽 모두 '한글 라벨' 열을 정확히 잡은 뒤에만 수행
    (열 불일치 상태로 비교하면 영문↔한글 가짜 신호 7,652건 발생 — 실측으로 확인된 함정)

### D-4c. 인스턴스 호환성 점검 (프로세스 지도 C4의 구현)
- CLI: `python -m dart_explorer taxcheck <전기 XBRL 패키지> --against <신버전>`
- 전기 인스턴스 사용 element 전수 ↔ 신버전 대조:
  1. 그대로 사용 가능 (녹색)
  2. **폐지됨** → D-3b 매핑 엔진으로 대체 후보 Top 4 자동 제시 (노랑)
  3. 라벨/Role 변경 → 변경 내용 표시 (파랑)
- 산출물: "당기 XBRL 착수 전 체크리스트" 엑셀 — 시즌 시작 시 클라이언트별 1회 실행

### D-4d. 확장→표준 승격 감지
- 대상: 코퍼스 extensions 테이블(7,906건 축적) + 자사 작성 확장
- diff의 "신설 element"와 라벨 매칭 (D-3b 스코어러 재사용: 자모편집거리+토큰자카드)
- 출력: "작년 확장 X ≈ 올해 신설 표준 Y (유사도)" 추천 — 확정은 회계사
- D-4c 리포트에 통합 (전기에 확장 썼던 항목은 승격 후보 자동 첨부)
- 참고: 신설 1,334개 중 특수관계자거래 세분화 계열 다수 —
  회사들이 확장으로 만들던 것의 표준화 흔적, 승격 감지의 실제 표적

### 게이트 D-4
1. 실파일 2세대 taxdiff → 기대값(1,334/156/7,652) 근사 일치
2. 홀드아웃 회사 1곳의 전기 인스턴스 taxcheck → 폐지 검출 + 대체 후보 제시
3. D-4d: 코퍼스 확장 중 신설 표준과 고유사도 매칭 사례 5건 이상 리포트

## 3. [A-3 확장] DART 편집기 버전 대응 (DSD)

### 방침 (불변)
1. **우리 도구는 meta.xml의 editver/docver를 절대 수정·창작하지 않는다**
   (근거: 밑바닥 생성 DSD의 스키마 검증 실패 사례 / 버전 변환은 편집기 고유 기능)
2. repack 산출물은 항상 뼈대 DSD의 버전을 그대로 상속
3. 위치 기반 extract는 직렬화 형식(줄바꿈·속성순서)에 무관 — 단 신버전마다 G2로 확인

### 새 편집기 버전 출시 시 절차 (KNOWN_VERSIONS.md에 명문화할 것)
```
1. 대표 DSD 1개(한빛정밀 클린본)를 새 편집기에서 열기 → 저장
   → 편집기가 변환한 파일 확보 (예: *_6_1변환.dsd)
2. 변환본을 fixtures/real/에 세대 추가
3. batch_validate: 변환본 extract → 무변경 repack → G2(내용 동일) 확인
4. 통과 → KNOWN_VERSIONS.md에 행 추가 (editver, 확인일, G2 결과)
   실패 → 직렬화 차이 리포트 후 진행 중단 (기획 세션 회신)
5. 이후 신버전 뼈대 사용 가능 (구버전 DSD는 편집기 하위호환으로 계속 열림)
```

### [소패치 A-3b] version-check 명령
- CLI: `python -m dsd_tool version-check <파일.dsd>`
- editver 추출 → KNOWN_VERSIONS.md 대조 → 미확인이면 위 절차 안내 출력
  + 즉석 G2 스모크(무변경 왕복 내용동일) 실행 결과 표시
- E-0 대시보드에 "확인된 편집기 버전" 카드 추가 (KNOWN_VERSIONS.md 렌더)

### 게이트 A-3b
1. 기존 세대(5.106/5.107/6.0변환) 3종에서 version-check 정상 판정
2. 가짜 editver 픽스처로 미확인 경고 + 안내 절차 출력 확인
