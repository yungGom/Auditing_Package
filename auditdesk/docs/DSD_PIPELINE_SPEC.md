## 2. 핵심 발견 (구조 불변식)

### 2.1 최상위 구조: 10/10 동일 ✅
```
BODY
├── INSERTION (정오표 placeholder)
├── COVER (표지: 기수/기간)
├── TOC (목차)
├── INSERTION (감사보고서 placeholder) ★본문 없음
├── SECTION-1 "(첨부)재무제표"
│     ├── WARNING (IFRS 안내)
│     ├── INSERTION × 7~8 (FS별 placeholder)
│     ├── 제목TABLE + 헤더TABLE + 데이터TABLE (FS별 반복)
│     └── SECTION-2 "주석"
├── INSERTION × 2 (부속명세서/내부회계)
├── WARNING (연결감사보고서는 없을 수 있음)
└── SECTION-1 "외부감사 실시내용"
      └── SECTION-2 × 4 + TE 셀 105개 (전 파일 동일 표준양식)
```

### 2.2 결정적 발견: 공시 DSD에는 감사보고서 본문이 없다
- `<INSERTION>◆click◆『감사인의 감사보고서』삽입</INSERTION>` placeholder만 존재
- 감사의견/강조사항/KAM 본문은 감사인이 DART 편집기에서 .dsl 라이브러리로 삽입
- **설계 결론 (확정): 도구 스코프 = 재무제표 + 주석 + 표지**
- 감사보고서 본문: 법인 표준 형식이 동일하므로 **표준 뼈대 DSD(법인 내부 작성본, 실제.dsd 형식) 1개로 일괄 처리**
  - 공시 DSD 기반 작업 시: 본문 placeholder 그대로 유지 (DART 편집기에서 삽입)
  - 법인 내부 DSD 기반 작업 시: 본문이 이미 있으므로 그대로 보존 (값 교체 대상 아님)
  - 본문 텍스트 추출/편집 기능은 만들지 않음 (실무 중요도 낮음, 문용님 확인)

### 2.3 재무제표 제목: TITLE 태그가 아니라 TD 테이블
```xml
<!-- 패턴 A: 단독 테이블 (삼성, 노무라, 홈플러스) -->
<TABLE ...><TR><TD ALIGN="CENTER" [COLSPAN="2"]>재 무 상 태 표</TD></TR></TABLE>

<!-- 제목 텍스트 변형 -->
"재 무 상 태 표"(공백) | "재무상태표"(무공백, 삼천당) | "반기재무상태표" | "연 결 재 무 상 태 표"
```
정규화 규칙: 공백/전각공백 제거 후 `^(반기|분기|연결)?(재무상태표|손익계산서|포괄손익계산서|자본변동표|현금흐름표|이익잉여금처분계산서|결손금처리계산서)$`

### 2.4 FS 개수: 4종 vs 5종
- 5종: 손익계산서 + 포괄손익계산서 분리 (삼성전자, LG화학)
- 4종: 포괄손익계산서 통합 (에코프로비엠, 삼천당제약, 금융사 전부)
- → 시트 생성은 "감지된 만큼 동적으로"

### 2.5 주석 헤더: SPAN USERMARK=" B" 패턴 (10/10 통일)
```xml
<P><SPAN USERMARK=" B">1. 일반적 사항</SPAN>&amp;cr;&amp;cr;본문...</P>
```
- 정규식: `<SPAN\s+USERMARK="\s*B\s*"[^>]*>\s*(\d+)\.\s*(제목)`
- 전 파일 주석 번호 1~N 연속, 누락 없음
- ⚠ 기존 v2 파서는 `SPAN ID=` 기반 → **실제 공시 DSD에서 주석 분리 실패했을 것**

### 2.6 빈 셀 처리
- `<TD></TD>` (start==end) 빈 셀 다수 존재 (파일당 100~500개)
- 위치 기반 방식에서는 빈 셀도 위치를 알고 있으므로 **새 값 삽입 가능** (이게 핵심 장점)

### 2.7 단위 표기
- `(단위 : 백만원)` / `(단위: 천원)` / `(단위 : 원)` / 복합 `(단위: 천톤, 백만원)`
- 스케일 변환은 하지 않는다 — 표시 그대로 추출/역변환 (감사인이 판단)

### 2.8 기타
- 인코딩: 10/10 UTF-8, CRLF (EUC-KR 파일명 이슈는 ZIP 레벨에서만)
- TE 셀(외부감사 실시내용): 전 파일 105개 동일 → 표준양식, ACODE 속성으로 식별
- 3월 결산(노무라) 존재 → 기수/일자 하드코딩 금지

## 3. 도구 아키텍처 (확정)

### 3.1 방식: 위치 기반 값 교체 (검증 완료)
```
[추출] DSD → 셀 스캔(TD/TH/TE/TU 오프셋 기록) → Excel + _MAP 시트
[편집] 사용자가 Excel에서 값 수정
[역변환] _MAP 비교 → 변경 셀만 오프셋 역순 교체 → 바이너리 ZIP repack
```
- 검증: 실제 DSD에서 2개 셀 수정 → XML 정확히 2곳만 변경, 크기 동일, 거짓변경 0

### 3.2 시트 구성 (추출 결과 Excel)
```
사용안내 | 표지 | [FS 시트들: 감지된 4~5개] | 1, 2, 3... (주석별) | 외부감사 | _MAP(숨김)
```

### 3.3 _MAP 스키마
| 컬럼 | 내용 |
|------|------|
| sheet | 시트명 |
| row, col | 엑셀 좌표 |
| xml_start, xml_end | contents.xml 문자 오프셋 |
| orig_raw | 원본 XML 텍스트(비교용, 200자 제한) |

### 3.4 비교 규칙 (거짓변경 방지)
1. 숫자: try_number()로 양쪽 변환 후 수치 비교
   - 천단위 검증: 첫 그룹 1~3자리, 이후 그룹 정확히 3자리 → "3,4,5,6"(주석참조)은 텍스트 유지
2. 텍스트: clean_text() (엔티티 해제, &cr;→\n, 태그 제거) 후 비교
3. 역변환 시 이스케이프 순서: \n→&cr; 먼저, 그다음 &→&amp;

### 3.5 역변환 규칙
- 변경 셀만 뒤에서부터(오프셋 큰 것부터) 교체 → 오프셋 밀림 방지
- ZIP repack: 원본 바이너리 구조 유지, contents.xml만 재압축 (LFH/CD/EOCD 수동 패치)
- 출력: `{원본명}_수정.dsd`, 원본 덮어쓰기 금지

## 7. ACCIO 엑셀 역분석 (템플릿 설계 반영)

> 동일 10개사의 ACCIO 변환 엑셀 분석 결과

### 7.1 시트 구성 (ACCIO 방식)
```
원문 | BS | PL | [PL 1] | CE | CF | 1, 2, 3, ... (주석 번호)
```
- `원문`: 전체 내용 통합 뷰 (삼성전자 기준 1,948행) — 참조용
- FS 5종일 때 `PL 1` = 포괄손익계산서 (동적 추가)
- 주석 = 숫자 시트명 (우리 설계와 동일 ✅)

### 7.2 FS 시트 배치 (BS 기준)
| 행 | 내용 |
|----|------|
| 1~3 | 제목/기수 (A:B 병합) |
| 4 | 회사명(A) + 단위(B) |
| 5 | 헤더: 과목/주석/당기(2열 병합)/전기(2열 병합) |
| 6~ | 데이터 |

- **당기/전기가 각 2열**: 개별 항목은 왼쪽 열, 소계·합계는 오른쪽 열 (DSD 원본의 계층 구조 반영)
- 주석 참조("4, 28")는 텍스트 유지 ✅ (우리 try_number 검증과 동일 접근)

### 7.3 주석 시트 배치
| 구성 | 방식 |
|------|------|
| 1행 | 주석 제목 ("4. 범주별 금융상품") |
| 서술문 | A열에 문단 단위 |
| 단위 | `(단위 : 백만원)` 별도 행 (테이블 직전) |
| 테이블 | 헤더행 + 데이터행, 여러 열 |

### 7.4 ACCIO의 한계 (우리 도구의 차별점)
1. **숫자가 문자열로 저장** (`'12581632.0'`) — 주석 테이블 전체. 엑셀에서 수식 계산 불가
   → 우리: try_number()로 진짜 숫자화 + 천단위 검증
2. **역변환(Excel→DSD) 정확도 검증 수단 없음** — 클라우드 서비스라 내부 로직 블랙박스
   → 우리: _MAP 위치 기반으로 변경분만 정밀 교체, 원본 대비 바이트 검증 가능
3. **외부 서버 업로드 필수** — 고객사 데이터 보안 원칙과 충돌
   → 우리: 100% 로컬

### 7.5 템플릿 설계 확정안 (ACCIO 장점 흡수)
- 시트명: `BS/PL/PL1/CE/CF` 약칭 채택 (실무 친화) + 주석 숫자 시트
- FS 시트: 당기/전기 2열 계층 구조 유지 (DSD 원본 충실)
- 단위 행: 주석 테이블 직전 단위 표시 행도 _MAP에 포함 (수정 가능)
- `원문` 통합 시트: P3 (추후) — 참조용으로만, _MAP 제외
